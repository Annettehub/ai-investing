# 投研实体档案卡网页生成提示词：GitHub 仓库适配版

## 任务与边界

将指定的投研实体 Markdown 渲染为可视化实体页，参考薄荷青绿投研工作台。
资料正文仍以现有 GitHub 仓库文件为唯一事实来源。网页是阅读层，不是第二套资料库。

- 默认只做本地预览。未经用户本轮明确授权，不 commit、不 push、不部署。
- 不改仓库权限、分支、文件组织、资料同步、入库流程和原始资料。
- 不覆盖输入提示词；适配文档另存。
- 不从提示词、参考截图中复制公司的数值、持仓身份或更新状态。
- 参考图只决定表现形式，不作为事实来源。

## 输入

1. 实体 Markdown 路径，如 `02-kb/entities/06181-老铺黄金.md`。
2. 原网站路径，用于保留原有链接和提供对照。
3. 可选的展示配置：需要强调的指标、章节到模块的映射。配置只能引用原文位置，不能维护第二份正文或数字。

现有文章可以继续采用标题加开头引用块记录代码、日期、状态等信息。
不要为满足前端要求强制修改原文为 MDX。若未来采用 YAML frontmatter，先扩展标准解析与测试，再接入；不得用正则猜测 YAML。

## 内容保真

1. 章节标题、正文、推导逻辑、证据、回报预期、保留意见、注释、来源必须完整呈现。
2. 允许更改布局及把表格转成模块，不得自动摘要、缩句、改写观点或合并相近判断。
3. 原文表格的所有单元格均须保留。图表新增在原表旁或上方；指标卡可以替代表格，但必须承载每列原始信息。
4. 保留原文中的“约”“推算”“机构估算”“待验证”、统计期间、币种及来源。不能把范围取中值画成精确数。
5. 原文自相矛盾或口径不同，只报告问题；未经授权不修改数据、不替作者消除分歧。
6. 未识别的章节、列表、表格回退为标准 Markdown，不丢弃。
7. 不伪造持仓标记、实时行情、今日更新、来源链接或健康评分。
8. 多空排序可以调整为左多右空，但各自论述、标点及引用必须完整保留。

## 章节识别

根据章节名称与表头识别模块，不依赖固定编号。
现有老铺文章的 0、0.1、1–15 及所有子章节保持原有顺序；不得强行套入参考稿的 0–13 编号。
未来文章尽量统一章节名称即可；不同章节编号应能复用同一模块。

| 章节语义 | 网页模块 | 保真要求 |
| --- | --- | --- |
| 一句话定位 / 核心投资论点 | 完整段落，重点由原文加粗表达 | 不重写 THESIS 或自行提炼争议 |
| 交叉检查结论 | 普通对齐表格 | 原文几列就几列，不做重复卡片 |
| 生意本质 | 原文列表、机制链条 | 机制中的每一步完整保留 |
| 业务划分 | 一张完整比较表 | 维度及业务名称表头只出现一次，列宽统一 |
| 护城河分层 | 等宽网格 | 每项保留层级、内容、定性判断、现状；不凑格数 |
| 竞争边界 | 核心 / 次要 / 潜在竞争者模块 | 每个原文段落及列表完整保留 |
| 多空张力 | 左绿右红的等宽双栏 | 等高由布局拉伸实现，不截断长文字 |
| 核心假设 | 按条目形成网格 | 推导、证据、回报预期缺一不可，不强行补出不存在字段 |
| 季度跟踪仪表盘 | 指标卡、原文状态及筛选 | 原文几项就几项；最新值、阈值和状态完整展示 |
| 证伪 / 风险 / 催化剂 / 管理层 | 表格加原文论述 | 定性等级不转换成虚构概率 |
| 财务数据 | 数据图表加完整原表 | 同期同口径比较；年与半年不能伪装成同比增长 |
| 估值 | 指标摘要加原文估值论述和表格 | 机构区间不等于统一估值，估算不冒充实时报价 |
| 待验证 / 附录 / 版本历史 | 原文列表、段落或表格 | 不省略看似重复的论述 |
| 来源 / 关联档案 | 完整清单、上标引用与真实链接 | 缺失链接标记待补充，不自行编造 |

## 图表规则

- 数值从 Markdown 解析出的对应单元格提取，不在组件里写公司数字。
- 年收入采用同年度分部对比；利润率按期间呈现；现金流正负分别显示。
- 每张图包含指标、期间、单位、精确标签以及原表入口。
- 金额柱状图从零起始；负值应有清晰零基线。颜色与文字同时表达含义。
- 区间值、缺失值、待验证值无法可靠图表化时保留文本或原表，不填零。
- 不将季度、半年、全年直接混成一条等周期趋势；不把“高/中/低”转换成百分比进度条。
- 状态来自原文，不能因图形好看而重新判定健康等级。

## 页面与视觉

- 桌面采用左侧站点导航、中央正文、右侧章节目录；平板收起右目录；手机导航可展开，正文一列。
- 主背景近白 `#FBFDFC`，导航浅薄荷 `#EFF8F4`，正文深色 `#192D29`，链接深绿 `#12654D`。
- 多方淡绿、空方淡红、待验证用琥珀色。文字必须清晰，禁止浅灰字压在浅色背景上。
- 正文章节不层层包成浮动卡片；卡片用于指标、假设、护城河等独立重复项。圆角统一 8px。
- 表格使用语义化 table / th / td、fixed 布局和 colgroup；窄屏仅表格容器横向滚动，整页不得溢出。
- 第一列作为标题/事项列，统一固定为 280px（约为原窄标题列的两倍），不随字段长度或屏幕宽度改变。从第二列起，所有内容列均分剩余宽度，不按正文长短或章节另设不同比例；四列内容就四列等宽，两列内容就两列等宽。每个内容列至少留 160px，窄屏在表格容器内横向滚动，不压缩标题列，不裁剪正文。
- 长业务名称和正文自然换行；不使用省略号、固定高度裁剪或缩小字体来藏内容。
- 表格外的注释独立放在表格下方；不塞进单元格。
- 不凭截图增加“持仓标的”或“今日更新”徽章。只有源文明确表达时才呈现。
- 引用序号在正文右上角呈现，链接到真实来源条目。不得把 HTML 标签或 `^^` 当成可见正文。

## 当前仓库技术适配

1. 继续使用现有 Astro / Starlight，不新增后端或改变 Pages 发布方式。
2. 新页采用独立 Astro 布局，显式导入实体页 CSS；与旧主题隔离，开发与构建使用同一份样式。
3. 不采用 build 后扫描 HTML 注入 CSS 的方式。后处理不能解决开发预览一致性，也不负责内容结构。
4. 用 remark / unified 的 Markdown 语法树识别章节、表格、列表、加粗与链接，不按管道字符手拆表格。
5. 老铺本地预览路由保留：`/ai-investing/preview/entities/06181/`。本次获准发布的正式路由只有老铺黄金、泡泡玛特、腾讯三条既有实体地址；通过三个显式 Astro 页面接入定制布局，其余网页仍由 Starlight 渲染。
6. 新页直接读取仓库 Markdown，源文件修改后自动重渲染；不手工维护生成 HTML。
7. 不自动推广到全站。正式实体页沿用原有网址，并加入 Pagefind 正文索引；页内搜索限定为“搜索本篇档案”。正式页不得带“本地预览”或 noindex 标记；预览页保留 noindex。
8. 不把 `03-raw/` 等原始资料批量复制到公开网页；链接和公开范围沿用既有边界。

## 验收与交付

- 完整性检查：每个章节、表格单元格及原文文本片段都能在对应模块找到；单独检查多空和核心假设。
- 数值检查：图表数值与对应原表一致，原文估算/待验证不丢失。
- 视觉检查：桌面、平板、手机截图；双栏对齐；无页面横向溢出；标题与内容不互相覆盖。
- 表格列宽检查：逐表测量首列固定 280px，第二列及后续内容列的宽度差不超过 1px；在桌面、平板、手机均检查，不能裁剪原文。
- 交互检查：目录定位及高亮、本篇搜索、指标筛选、窄屏导航、键盘焦点、来源链接。
- 构建检查：现有站点 build 成功，旧路由仍可访问，源 Markdown 无改动。
- 交付本地预览 URL、适配后的提示词、已完成检查和未验证事项。
- 默认不推送；只有用户随后明确要求发布，才进入提交与部署流程。
