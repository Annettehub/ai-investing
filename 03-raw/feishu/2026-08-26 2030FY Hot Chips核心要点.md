AMD MI455 以及 Helios 机架级 AI 系统
发⾔⼈： Steve Scott，David 和 Krishna，AMD
摘要： AMD 展示了 Helios，这是⼀个围绕 MI455 GPU、EPYC CPU、Infinity
Fabric 和可编程 Pensando ⽹络构建的 72-GPU 机架级系统。重点在于内存语义以太⽹扩展（scale-up）、全机架弹性、液冷技术以及从电信号到光信号扩展的转变。
1. Helios 将 72 个 MI455 GPU 整合为⼀个紧密耦合的系统
Helios 由 18 个节点组成，每个节点包含⼀颗 EPYC CPU 和四个 MI455
GPU。AMD 表示，该机架可提供近 1.7 PB/s 的总 HBM 带宽，扩展⽹络双向带宽超过 0.25 PB/s，且横向扩展（scale-out）带宽超过 40 TB/s。该架构旨在使整个机架表现得像⼀个单⼀系统，⽽⾮独⽴服务器的集合。AMD 在每四个 GPU 中使⽤⼀颗 CPU，并表示⼴泛的建模显示，这种配置提供了最佳的性价⽐，并拥有⾜够的 CPU 吞吐量来维持加速器的数据供给。
2. AMD 正在通过以太⽹实现直接内存操作
MI455 GPU 在扩展集群（scale-up pod）中⽀持直接加载（load）、存储（store）和原⼦操作（atomic）。AMD 将这些内存事务封装进以太⽹帧中，并通过 AVGO Tomahawk 6 交换机进⾏路由，访问机架内任何 GPU 内存最多仅需⼀跳交换机。⼀旦远程内存被导出并导⼊到另⼀台 GPU 的虚拟地址空间，软件就可以像访问本地内存⼀样对其进⾏访问，尽管其性能表现有所不同。GPU 内部的 DMA 引擎负责处理⼤部分数据迁移，⽽不会占⽤计算资源。
3. 这可能是 AMD 最后⼀代全电信号扩展架构
AMD 表示，Helios 已接近全电信号扩展织⽹（scale-up fabric）的物理极限。由于传输距离受限，电信号连接迫使 GPU、交换机和线缆必须采⽤极⾼密度的物理配置。AMD 预计将在下⼀代产品中开始引⼊光信号扩展，这将解耦计算拓扑与机架布局之间的关联。光通信将允许更⼤的物理间距和更灵活的封装⽅式，⽽不再要求每个加速器和交换机都必须挤在⼀个受到严格限制的电信号域内。
4. Helios 采⽤直接液冷技术，但 AMD 预计机架密度不会再有重⼤⻜跃
Helios 超过 85% 的热量通过直接液冷移除，液冷计算托盘和交换机托盘通过快速断开接头连接。在被问及机架功率如何演进时，AMD 表示不同的数据中⼼运营商有不同的⾸选运⾏范围，但预计功率密度不会在当前⽔平基础上⼤幅增加。向光学扩展（optical scale-up）的转变应该会减少为了保持信号传输距离⽽不断追求物理密度的需求，从⽽让系统构建者在布置电⼒和冷却基础设施时拥有更⼤的灵活性。
5. Pensando AI NIC 围绕部署后的可编程性设计每个 GPU 可以直接连接到多个 800G Pensando AI NIC，为每个 GPU 提供⾼达约 2.4 Tb/s 的横向扩展（scale-out）⽹络带宽。AMD 刻意避开了固定功能的⽹络设计，因为 AI 传输协议、拥塞控制⽅法和遥测需求的变化速度太快。该⽹卡使⽤可编程的数据包处理和 DMA 流⽔线，⽤于虚拟化、加密、RDMA 传输、负载均衡和遥测。在系统出货后，协议和拥塞算法仍可以通过固件持续演进。
6. 多路径传输、拥塞控制和遥测正成为加速器架构的⼀部分
AMD 描述了将单个 GPU 到 GPU 的流分散到多达 128 或 256 条路径上，以提⾼⽹络利⽤率并避免低熵流量模式。可编程传输层可以⽀持选择性重传、移除降级路径、探测恢复并实现客户控制的源路由。拥塞控制可以针对每个数据包的 RTT、丢包或 ECN 标记做出反应，⽽⽆需等待主机 CPU 或驱动程序。硬件遥测可以按接⼝、队列对或路径跟踪统计信息，并仅流式传输客户选择监控的事件。
7. 整机架机密计算和故障隔离已融⼊设计之中
AMD 表示，Helios 通过数据包级 AES-GCM 加密、设备认证、安全分区和受保护的执⾏环境，⽀持跨机架的机密计算。机架可以划分为虚拟 Pod，以提供性能、安全和故障隔离。扩展结构（scale-up fabric）旨在单个链路、交换机 ASIC 或整个交换机托盘失效时仍能正常运⾏。流量会⾃动重新路由，丢失的数据包会⾃动重传，⽽发⽣故障的交换机托盘可以在线更换并重新投⼊使⽤，⽆需关闭整个机架。
8. AMD 在保留专有事务层的同时利⽤以太⽹⽣态系统
AMD ⽀持以太⽹的理由是，它提供了成熟的交换机、线缆、连接器、管理⼯具和庞⼤的供应商⽣态系统。以太⽹之上的内存事务协议仍针对该⽤例进⾏了定制，具有轻量级报头、动态数据包封装和端到端重传功能。AMD 将这种⽅法与联盟开发的 UALink 协议进⾏了区分：两者都承载内存事务，但
AMD 的设计将其封装进以太⽹帧并实现可靠的端到端传输，⽽ UALink 则采⽤不同的逐跳（hop-by-hop）模型。
NVDA Vera CPU 助⼒代理式 AI（Agentic AI）
演讲者： Jonathan Evans 和 Polychronis Sakalakis，NVDA
摘要： NVDA 设计 Vera 的核⼼理念是，代理式 AI（Agentic AI）使 CPU 再次成为推理循环中的关键环节。该架构优先考虑⾼单线程性能、负载下的可预测吞吐量、海量⼀致性带宽以及机架级机密计算。
1. 代理式 AI 将单⼀查询转化为全系统⼯作负载
Olympus 核⼼包括⼀个⼤型神经分⽀预测器，⽀持每周期两个已跳转分⽀，拥有 108 字节的指令获取路径，并通过融合技术每周期解码超过 10 条 ARM指令。后端可容纳 1,000 多条指令，每周期可执⾏四次加载、两次存储和六次向量操作。它还包含⼀个 96 KB 的 L1 数据缓存、⼤型转换结构、激进的预取机制，以及⼀个专⻔针对 NVDA 预期的代理系统（agentic systems）中⼤量图计算负载⽽设计的图预取器。
5. 空间多线程旨在减少“吵闹邻居”效应
Olympus 并没有采⽤传统的 SMT（两个线程竞争许多相同的结构），⽽是使⽤了 NVDA 所谓的“空间多线程”（spatial multithreading）。每个线程拥有基本独⽴的流⽔线、分⽀预测、调度器和寄存器资源，同时共享缓存和浮点单元等选定的昂贵结构。NVDA 表示，当第⼆个线程需求增加时，这种设计能提供更稳定的性能，有助于维持服务⽔平⽬标（SLO）。该设计还减少了当⽆关线程共享更多微架构状态时可能出现的侧信道和⼲扰问题。
6. Vera 采⽤单⼀⼤型计算裸⽚，⽽⾮将核⼼分散在多个⼩芯⽚上
Vera 由六个裸⽚（die）组成：⼀个⼤型计算裸⽚、四个 LPDDR5X 内存裸⽚和⼀个系统 I/O 裸⽚。NVDA 选择单体计算裸⽚是为了避免核⼼到核⼼以及核⼼到缓存的流量在芯粒（chiplet）边界移动时产⽣的延迟、功耗和带宽损失。所有核⼼共享⼀个平⾯的 164 MB 末级缓存，⽽内部⼀致性结构提供⾼达 3.4 TB/s 的对分带宽。独⽴的内存裸⽚通过低延迟的 NVLink C2C 变体进⾏连接。
7. 内存和 I/O 带宽的配置旨在为 Rubin 提供持续供应
Vera 提供约 1.2 TB/s 的 LPDDR5X 带宽，NVDA 表示这⽐传统服务器内存提供了更好的每瓦带宽。该 CPU 还包含 96 通道的 PCIe 6.0 并⽀持 CXL
3.1，双向 I/O 总带宽约为 1.5 TB/s。其第⼆代 NVLink C2C 连接提供约 1.8
TB/s 的原始 CPU-GPU 带宽。NVDA 的设计⽬标是防⽌ CPU、内存或 I/O⼦系统成为与其连接的 Rubin 加速器的瓶颈。
8. 机密计算已在 CPU、GPU 和机架层⾯实现
Vera Rubin 专为机架级机密计算⽽设计，⽽⾮仅限于单⼀处理器的保护。
CPU 和 GPU 可以验证请求是否属于正确的虚拟机（VM），同时每个虚拟机都会获得独⽴的加密上下⽂。数据在内存中以及链路传输过程中均经过加密，但在受保护的 CPU 和 GPU 域内部可以以明⽂形式进⾏处理。NVIDIA表示，该硬件与其软件安全堆栈协同⼯作，可保护整个 AI ⼯⼚的模型、智能体上下⽂、⽤户数据和推理过程。此外，NVIDIA 还提到，在特定的流媒体测试中，Redpanda 的性能较传统 CPU 提升了约 6 倍。
INTC Diamond Rapids 与全新的扇出型（fan-out）Xeon 架构
演讲者： Krishna，INTC Fellow 兼 Xeon CPU ⾸席架构师
摘要： INTC 推出了⼀种全新的扇出型架构，将可扩展的计算构建模块与集中的内存及 I/O 中⼼分离。Diamond Rapids 是该架构的⾸个实现版本，集成了256 个 P 核、1.28 GB 共享缓存、16 个内存通道以及 128 条 PCIe 6.0 通道。
1. 扇出型架构实现了计算与内存及 I/O 的分离每个可扩展的计算构建模块包含多个堆叠在基础芯⽚（base die）上的核⼼⼩芯⽚（core chiplets）。核⼼⼩芯⽚包含 CPU 核⼼和私有缓存，⽽基础芯⽚则承载共享的末级缓存以及与集中式织⽹中⼼（fabric hubs）的接⼝。
INTC 可以灵活调整⼀个构建模块内的核⼼⼩芯⽚数量，以及最终封装中的构建模块数量。内存控制器、⼀致性、CXL 扩展、I/O 和加速器被移⾄独⽴的织⽹中⼼，⽽不是在每个计算瓦⽚（compute tile）中重复设置。
2. 统⼀内存延迟是核⼼架构设计的⾸要任务每个计算构建模块都直接连接到每个内存和 I/O 织⽹中⼼，避免了通过相邻计算或 I/O 瓦⽚的中间跳转。事务按地址分布在各个中⼼，但所有核⼼都保留对完整内存⼦系统的直接访问权限。INTC 表示，这在整个封装内提供了低且相对统⼀的内存延迟，⽽不是让某些核⼼在物理上⽐其他核⼼更接近某些内存通道。同样的⽬标也促使公司决定采⽤ UCIe-S 封装连接，⽽⾮密度更⾼但传输距离较短的替代⽅案。
3. Diamond Rapids 可扩展⾄ 256 个 P 核和 1.28 GB 共享缓存第⼀种实现⽅案包括四个计算构建模块，总共包含 16 个计算⼩芯⽚（chiplets）。在整个封装中，Diamond Rapids ⽀持多达 256 个⾼性能 P核和约 1.28 GB 的末级缓存。内存系统拥有 16 个通道，⽀持 DDR5-8000及更快的 MRDIMM 配置，峰值带宽约为 1.6 TB/s。I/O ⽅⾯包括 128 条
PCIe 6.0 通道，以及另外 8 条⽤于系统管理和基础设施的 PCIe 4.0 通道。
4. 该封装结合了 3D 混合键合与解耦式织⽹中⼼（disaggregated fabric四个计算⼩芯⽚通过混合键合（hybrid-bonded）技术连接到每个基础晶圆（base die）上，构建了⼀个跨越两层路由器的 3D 织⽹。INTC 表示，计算⼩芯⽚采⽤ Intel 18A 系列⼯艺，⽽基础晶圆则采⽤⽀持 TSV 的 Intel 3 ⼯艺。独⽴的内存和 I/O 中⼼通过 UCIe-S 连接。这种结构使 INTC 能够主要在有利于提升 CPU 性能的地⽅使⽤先进⼯艺，同时将缓存、路由和 I/O 功能置于更合适的⼯艺节点上。
6. 电源管理按⼯作负载域进⾏分布式处理这种层级化设计为核⼼、缓存、内存和 I/O 创建了独⽴的电压和频率域。硬件会监控 I/O 带宽、内存带宽以及核⼼对内存延迟的敏感度，然后独⽴调整相关域。Diamond Rapids 还⽀持优先级核⼼，允许软件识别出⼀⼩组为外接 GPU 提供数据的 CPU 核⼼，并让这些核⼼保持更⾼的频率和优先级。其余 CPU 资源可以在较低功耗下运⾏，⽽不会使关键路径上的加速器陷⼊饥饿状态。
7. APEX 实现了 x86 指令集的现代化
Diamond Rapids 引⼊了⾼级性能扩展（Advanced Performance
Extensions，简称 APEX），包括新增的通⽤寄存器、三操作数指令、标志位分离以及新的条件执⾏能⼒。INTC 表示，这些改进减少了执⾏相同任务所需的指令数量，并且已经合并到开源和商业编译器的上游代码中。该核⼼还保留了 AMX 和 AVX 加速功能，⽽ I/O 中⼼则包含⽤于压缩和加密的
QAT、⽤于数据移动的 DSA 以及⽤于分析和扫描的 IAA。
8. 安全性和 RAS 已集成到共享架构中
Diamond Rapids ⽀持⽤于受保护虚拟机的 TDX、⽤于应⽤级⻜地的 SGX以及更⼴泛的 Xeon 安全堆栈。INTC 重点介绍了⼀种⽚上侦听过滤器（on-die snoop filter），它避免了以往在内存完整性元数据与 ECC 容量之间的权衡。将此功能保留在封装内还降低了获取缓存⾏所有权所需的延迟。该架构包括 I/O 缓存、内存加密和分布式错误遥测，并在各⼩芯⽚（chiplets）之间实现了集中式策略与本地功耗或恢复决策。
INTC Crescent Island：⾯向⾼容量智能体推理
演讲者： Sumit 和 Hongjie，INTC
摘要： Crescent Island 是 INTC 基于全新 Xe3P 架构打造的 350W 推理
GPU，具备超⼤容量的 LPDDR5X 内存。INTC 的⽬标是针对智能体（agentic）和稀疏模型⼯作负载，这些负载需要极⾼的内存容量，但⼜希望避开 HBM 的⾼成本和⾼功耗。
1. Crescent Island 提供⾼达 480 GB 的 LPDDR5X 内存，功耗约为 350W
INTC 的参考卡标准容量较低，⽽ ODM 和系统合作伙伴可以为每颗 GPU 配置约 160 GB ⾄ 480 GB 的 LPDDR5X。该芯⽚针对 350W 的功耗范围进⾏了优化，因此可以在相对简单的被动⻛冷数据中⼼系统中运⾏。INTC 选择
LPDDR5X 是因为它能提供⼤模型和⻓上下⽂所需的容量密度，同时与基于
HBM 的⽅案相⽐，能保持能效并降低成本。
2. 稀疏模型正在将内存容量与活跃带宽需求解耦
INTC 认为，新型稀疏 MoE 模型可以在不按⽐例增加每个 token 激活参数量的情况下，使总参数规模变得更⼤。完整模型、KV 缓存和多个会话仍需驻留在内存中，但在每个推理步骤中可能只需读取⼀部分权重。这使得设计需求转向了更⾼的容量，⽽不是让带宽随模型总规模线性增⻓。Crescent
Island 正是围绕这种新兴的“重容量”⼯作负载特性⽽设计的。
3. Xe3P 提升了矩阵计算密度并扩展了精度⽀持
Crescent Island 在低功耗待机模式下的⽬标功耗约为 10W，⽽其主动设计点功耗为 350W。INTC 强调，⼤型推理集群并不会让每个加速器始终保持满载，因此待机和部分利⽤率下的效率在⼤规模数据中⼼层⾯具有重要意义。该芯⽚采⽤分布式电源管理以遵循最佳电压-频率⼯作点，并将计算单元布置在中央缓存和织⽹（fabric）周围，以改善散热和供电。
6. 该设计⽀持标准 PCIe 扩展和多模态推理
Crescent Island 通过标准 PCIe 连接到主机和其他加速器，⽆需专⽤的机架织⽹。该 GPU 还包含多个视频编解码引擎，因此多模态⼯作负载可以即时压缩和解压缩数据，⽽不会消耗额外的主机资源或 I/O 带宽。INTC 的⽬标⼯作负载包括语⾔模型、推理模型、视觉和多模态推理，通过标准交换基础设施在节点内或跨节点连接多个 GPU。
