豆包要点总结
1. Transformer 三条路线——Encoder-only（BERT）、Decoder-only（GPT）、Encoder-decoder（T5）——最终收敛到最简单的 Decoder-only：样本效率高、KV Cache 推理友好、In-Context Learning 天然；GLM 曾尝试统一两类预训练目标，超大规模后也回归 Decoder-only。
2. 涌现能力：Jason Wei 等在百余个任务上观察到百亿、千亿规模附近性能跳变；Schaeffer 等指出跳变来自离散、非线性度量，换成连续度量后是平滑增长；统一到预训练 Loss 维度，Loss 降到某一区域后下游能力自然出现转折。
3. 能力演进路径：知识饱和之后是 Tool Call、Coding、Computer Use，再走向物理世界；每个阶段都会长出对应时代的 Agent，又被下一个更大的模型覆盖，Agent 之路逐步推进。
4. Scaling Law：Kaplan 给出计算量、数据量、参数量与 Loss 的幂律关系，主张参数优先、数据亚线性增长；Chinchilla 修正为参数与数据同比增长（约 1:20），在固定预算下求最优模型规模；工业界还要计入全生命周期推理成本，即 Token 经济。
5. 未来 Scaling 三条路线：更多真实人类数据、重复训练已有数据、合成数据筛选闭环；扩展时需同时考虑 Pre-training、Post-training、Inference 与 Agent 多个维度。

Transformer 的技术来源：去除循环与卷积
Attention 里关联关系的权重变得更重要：每个词看自己跟哪些词更相关。上节课讲 Transformer 里四个核心技术，第一个是删掉 Recurrence，也就是循环。删掉循环的逻辑很简单。
原来是 Sequence，必须一个一个算，速度慢，没法并行。最近有人说，整个计算机的发展就是让计算变得更并行，这有一定道理。如果不能让计算量爆发，计算机相对人的优势很弱；如果大规模并行计算成为可能，它相对人的优势就越来越大，自动化才变得可能。
所以第一件事是删掉循环。在这之前，2017年5月，Facebook 和 Google 在竞争谁的科研进展更快。那时还不叫大模型，大家还在做人脸识别、图像识别。
Facebook 有杨立昆，Google 也有 Jeff Dean 等很强的人，双方竞争，也知道对方的大概情况。像今天的大模型公司一样，细节和准确发布时间不一定知道，但大概知道友商这个月要发什么，自己也会抓紧发。当时知道 Google 要发一个听起来很厉害的新算法，Facebook 就赶紧把 Convolutional Sequence to Sequence 拿了出来。
模型也很优美，上节课讲过。它实现了并行，不再按序列一个一个算，因为卷积神经网络本身就能做大量并行计算。但要实现任意位置之间的长距离关联，就必须用多层网络。
需要做分层结构，还要设计感受野，这也很烦。Transformer 比它晚一点出来，首先要解决这两个问题，选择了 Attention。这也是很优美的设计，可以并行，可以做大规模计算。

语言模型的三条架构路线
从2018年开始，很多人训练不同模型，继续扩大规模。Google 一开始训练了不少不同模型，当时也已经使用 MoE。早期 MoE 和现在有不小差别，那时专家的粒度比较粗，现在是非常细粒度的 MoE。
当时训练了不少模型，但还没有效果特别好的大规模爆发，直到 GPT、BERT、T5 这些模型出来。GPT 最先出现，2018年训练了第一个版本，一个多亿参数，效果没那么好。GPT 是 Decoder-only 模型，只有一亿多个参数。
生成文本有时候连主谓宾都不完整。拿它微调使用也不太好。从今天回顾，GPT 更适合 Few-shot 和 Zero-shot，不是天然适合逐个任务做 Fine-tuning 的模型。
直接生成，或者加一点 Context、Prompt 和 Few-shot，效果可以更好。但当时参数小、效果不好，一直不温不火。随后 BERT 出来，也参照了一亿左右的参数规模，为了跟 GPT 对比。当时大家觉得 BERT 是一个 General Model，什么都能做。
现在回头看，我们都是马后炮。BERT 本质上学了一个表示。学到通用表示以后，拿到任何场合使用，还得微调，在最后一层加点东西。后来 GPT-2、GPT-3 把 BERT 盖过去，BERT 又有 DeBERTa、RoBERTa、ELECTRA 等很多改进。

BERT 的掩码语言模型任务
原本没有一个特定的自然语言处理任务，我们在做 Unsupervised Learning，学习一个表示。BERT 人为加了学习任务，什么叫学习任务？第一个是 Masked Language Modeling，把几个词盖掉，再学习恢复它们。学习过程中不停 Recover 缺失的内容，相当于做 Prediction。当时选15%的 Token，但这15%内部又做了一些划分。其中80%直接换成 [MASK] 这个符号，10%换成随机单词，另10%保持不变。为什么选15%？我们后来探讨很久。BERT 的作者 Jacob Devlin 刚发论文时，我请他来中国做过报告。
当时论文刚发表，还请得动，中美关系也比较好。我问他为什么选85%与15%的配比，他说也不知道，试了很多次，发现效果不错。后来我又去 Google 跟他们讨论，发现数值也有一些道理，有点像 Random Walk。大家知道 PageRank 的随机游走吗？85%的概率沿着链接跳到相应页面，15%的概率随机跳到其他页面。随机跳转与 Mask 掉内容，从某种角度上有相似之处。原本 Next Token 是确定的，现在允许随机跳到其他位置。PageRank 有详细的理论讨论，大家有兴趣可以看15%、85%这些配比。

下一句预测任务
Masked Language Modeling 是把内容遮掉再恢复。第二个任务是 Next Sentence Prediction，判断后面是不是下一句话。听起来有道理：生成过程中能判断马上进入下一句话。但后续很多研究觉得 NSP 没那么大意义。为什么？假设做 Next Token Prediction，能够预测句号，就已经知道这句话结束了。如果这个都能预测，为什么还要专门加 Next Sentence Prediction？大家可以认真想一下。这种人为设计的任务，规模还没上去时可能有意义。当你继续 Scaling，原来看起来很优美的设计，慢慢就没有那么重要，包括刚才说的85%、15%。今天的主题就是 Scaling。

正文
自回归与 Decoder-only 模型
它本质上是在任何一句话里预测下一个 Token。比如“The movie was great”，预测 Next Token。你可能问，那怎么拿它做分类？这句话是好还是不好，怎样判断？
很简单，规定下一个 Token 是 Yes 或 No，或者输出好、不好，就成为情感分类。大家由此发现，貌似所有任务都能变成生成。原来分类与表示学习是分开的，就像 Supervised、Unsupervised、Semi-supervised Learning 那样分开。
原来先用无监督学习学表示，再去做 Downstream Task；现在把任务合在一起。预测结果可以是分类，看起来像监督学习，但预训练本身又没有人工 Label。它不再特别区分监督还是无监督，就是一个简单的 Predicting Next Token。直到今天，仍有人问：大模型只做 Next Token Prediction，为什么还能做聪明的推理，什么都能做？等一下在 Scaling 部分再看这个问题。另一个很重要的点，也是计算机专业特别看重的，是生成过程中的计算复用。
做 K、V 计算时，前面已经算过的结果可以存下来直接用，每次只加入一个新 Token，再接着算。计算机最喜欢这种方式，否则每次都把前面循环重做，计算量巨大。复用 KV Cache，可以大大减少计算。
当时看起来，这项优势好像不算什么，因为模型很小。一亿参数的模型，可能几天或者一周就训完。即使机器少，也能几天训完，今天训这么小的模型就更简单了。KV Cache、从左到右计算，以及把任务变成 Conversation，这些优势当时没有体现得那么明显。如果一天就能训完 BERT，你会觉得训一个也无所谓。
来了一个下游任务，再微调一两个小时继续用，也没关系。但到了千亿、万亿模型，一个任务可能要调几天，手上几百个任务根本调不过来。等调完，下个模型版本出来了，前面的微调又过期了。

More Is Different：规模与描述层级
东西越来越多时，不能继续只从原来的维度看。人由原子组成，但不能只用原子解释人的行为，问一亿个原子为什么能说话，100个原子为什么不会。Transformer 吸收很多技术，成为优美模型；大模型又以 Transformer 为核心构建了操作系统。大模型不只是一个 Transformer，Transformer 也不只是一个 Attention。从 Scaling 角度看，参数、数据、计算增加，可能带来新能力。小规模时，看到的是分类精度、表示效果这些维度的改善。逐渐变大，就到了 Next Level of Description，要用另一层描述理解它。还用原子层面的方式衡量人，就没意思了。大模型也是这样，每种能力逐渐提升，理解整个系统也需要跟着变化。
我上次画过一张图，这是我最近经常画的一个图。第一个是知识，因为它是常识知识的表示，你先把知识做到头。知识能力做到头以后，我们还天天纠结知识，它已经饱和了。像一个人，当知识满载了，你想干什么？肯定想跟外界交互。早期第一件事就是要跟外界交互，要做 Agent。

GPT-4做了一个很简单的突破，就是调用工具。我为什么调用工具？其他主要是知识类，调用工具才跟外界有了交互。但光靠这么几个方式远远不够。要做更复杂、更多事情，Coding 更本质，必须把 Coding 能力提高，因为 Coding 是跟外界交互最本质的东西。

Kaplan Scaling Law 的符号与实验设置
2020年 OpenAI 写了《Scaling Laws for Neural Language Models》。OpenAI 在那个时代做了很多贡献。Kaplan 当时是约翰斯·霍普金斯大学的教授。他原本做量子场、弦理论，后来做了 Scaling Law。有人觉得这太厉害，但也不是完全从零开始。2017年百度已经有人研究深度学习里的缩放规律；再往前，2012年 AlexNet 时，Ilya 就提出一定要做大，只是当时没把 Scaling 讲得那么明确。Dario 也在百度待过，我想应该也受到一些 Scaling 思路的影响。到 OpenAI 后，他和 Kaplan 等人一起做了这篇论文，所以课件写 Kaplan with Dario。
Scaling Law 并不是说只要“傻大”就有用。涌现能力告诉大家，扩大后能力会上升，无论看连续变化、间断变化，还是用 Loss 统一描述。而 Scaling Law 进一步告诉你，变化趋势是 Predictable，可预测的。并且要跨很大的尺度。100亿参数去预测200亿，意义不大，还不如直接训200亿。你必须能用100亿模型预测到1万亿时会怎样，这才是 Scaling Law 最本质、对研究最有帮助的地方。想想，训完10亿就能预见1万亿的效果，会有多大价值。
你可能说，得拿出来看数学、语文的 Performance。但刚才已经说，用 Loss Function 做统一，因为模型都在学广泛知识，任务维度相近，可以用共同的 Loss 观察。都是无监督学习，任务也类似，所以对比 Loss。这种大一统是大模型很美妙的一点。Scaling Law 给出三个重要结论，第一个是计算量增加。

Kaplan 的计算最优分配
根据前面的公式，可以算固定预算怎样分配。Kaplan 对最优参数量给出的指数约0.73，还有 Batch Size、训练步数和数据规模之间的关系，不能只盯参数。按 Kaplan 的配方，要把模型做得很大，数据不必同比增加，它是亚线性的。后来 Google 的 Chinchilla Scaling Law 又调整了系数。

通过小模型预测大模型表现
现在要分析模型精度很难。给你两个模型，问哪个好、哪个差，分析一周都未必能得到结果。你只能跑一些问题，但可能被 Overfit，结果也不一定可靠。长尾范围很广，很难充分测试。做模型的人如果都不能有效评测，怎样训练？Scaling Law 提供一条路：在小 Scale 调架构、调数据配比，先训4B、8B、16B，画出一条曲线，再预测1000B时可能是什么效果。
甚至预测10T。先说，不一定准确，但 Roughly 有用。GPT-4 的图也是用前面几个点拟合，再预测最终规模，计算量相差多少？相差1000倍。用约千分之一计算量，预测 GPT-4 训完后的 Loss，是一个非常优美的结果。所以 Kaplan 等人的工作对后世影响很大，让参数、数据、Loss 真正能被数学公式化。
原来做机器学习，经常拿一个模型，调整数据配比扔进去跑，再看最终数据集结果。因为不知道模型训出来会怎样，只能先试。结果不好，就做 Error Analysis，拿错误样本看原因，再调样本、调特征，扔回去继续。现在有了系统指导：应该怎样训、怎样配比，以及可能得到什么结果。原因也是成本结构变了。原来主要成本在设计算法，跑一次无所谓；现在大部分成本在真正跑那一次，所以必须事先预测。这是非常重要的改变。参数和计算之间的比例也值得仔细思考。

训练计算量为什么约为 6ND
每个 Token 对应算力成本，最后是一笔经济账。训练计算量跟参数、数据规模大约是 C≈6ND。为什么6ND？每个 Token 的前向计算，主要矩阵乘粗略是2N，D个 Token 就是2ND。Backward 要算梯度，包括对应权重梯度等，粗略是前向两倍，即4ND，所以合计6ND。先忽略 Embedding 等部分，这是一个总计算量的粗略公式。

Chinchilla 寻找最优参数与数据的三种方法
看 Chinchilla 左边的图，每条曲线都固定了计算预算。纵轴是 Loss，横轴是参数量。模型从小变大，Loss 会先降后升。这合理吗？参数过大、计算不增加，相当于没训练充分，Loss 反而高。所以固定计算预算时，实际上要选曲线最低点，也就是最合适的 Model Size。不同预算下都做这件事。把各条曲线的最低点连起来，就是最优选择的前沿。中间和右边展开这个结果：横轴是计算量，中间纵轴是参数量，右边纵轴是训练 Token 数。
它们也能看到 Scaling Law 的规律。这是2022年 Google 的 Hoffmann 等人发表的 Chinchilla 论文。左边有一组曲线，中间、右边各有一条关系，三者一起给出启示。要做全局优化，可以把它们放进同一个 Loss Function。里面 E 可以理解成不可约的熵下限。前面说的统一维度，就是把这些模型的训练都放到 Loss 上看。Loss 越小越好。如果数据和任务类似，模型做的事情就相似。刚才有人问 Tokenization 不同怎么办，如果你的 Tokenization 不如另一种，那理论上应该使用更好的。全世界大模型的训练和学习，某种程度上变得统一。

Decoder-only 模型的能力与优势
最后胜出的反而是更简单的 Decoder-only。快速总结，它就是预测 Next Token，问题和方式都非常简单。为什么这样一个简单模型最终赢了？T5 从某些角度看设计更合理，BERT 也有很多优美设计。第一，Decoder-only 的样本效率高，使它容易快速 Scaling Up。第二，假设所有任务都能描述成 Next Token Prediction，它能覆盖的任务就最多。Encoder-decoder 像 T5，任务转换多多少少更复杂。第三是很多人忽略的，只有这样做，推理才最简单。训练模型时，有人会想先训完，推理以后再管，但后来的模型必须认真考虑推理。
模型真正使用时，怎样推得快，决定了架构为什么要这么做。比如我刚提到的 DeepSeek 4.1 Flash，有一些很巧妙的设计，重点是减少 KV Cache。你可能问，KV Cache 不是能减少计算吗，为什么还要减少它？因为模型很大时，它在内存里也占空间。模型可能先占掉80GB，一共96GB内存，只剩一点。KV Cache 有时还要占30%，几十GB，根本放不下。比如刚才说华为950、96GB的设备，剩不了多少空间，就没法用了。设计还得考虑真正使用时怎么办。4.1版本我觉得很有意思，大幅减少 KV Cache 的内存占用，速度也快。当然快也可能是用了 B 系列卡推理，但减少 Cache 本身仍是很值得看的设计。

非线性度量与连续度量的对照
他们把这张图拿出来，最后的回答可以理解成 Yes and No，存在也不存在。什么意思？当你用非线性或者不连续的 Score 衡量，就会看到涌现。什么叫不连续？比如预测一个 Token，对就是1，错就是0。它是一个离散判断。若换成连续或线性的度量，看到的可能就是连续增长。这个说法有道理：输入能力缓慢提高，输出指标可能也连续提高，非线性指标才容易出现明显跳变。

课堂问答（一）
连续预测多个 Token 的整体正确率
数学上也可以解释。假设每个 Token 的预测满足某种规律，要连续预测 L 个 Token，最终的整体正确率就取决于这些 Token 是否全部正确。模型比较弱时，每个 Token 的精度只有0.5，连续 L 个都对就是0.5的 L 次方，非常低。能力提高到0.9，就变成0.9的 L 次方，两者差距一下拉大。比如5个 Token，单个 Token 的差距看着没那么夸张，要求5个都对，差距就出来了。他们还做了检验。

More Is Different：规模与描述层级
东西越来越多时，不能继续只从原来的维度看。人由原子组成，但不能只用原子解释人的行为，问一亿个原子为什么能说话，100个原子为什么不会。Transformer 吸收很多技术，成为优美模型；大模型又以 Transformer 为核心构建了操作系统。大模型不只是一个 Transformer，Transformer 也不只是一个 Attention。从 Scaling 角度看，参数、数据、计算增加，可能带来新能力。小规模时，看到的是分类精度、表示效果这些维度的改善。逐渐变大，就到了 Next Level of Description，要用另一层描述理解它。还用原子层面的方式衡量人，就没意思了。大模型也是这样，每种能力逐渐提升，理解整个系统也需要跟着变化。
我上次画过一张图，这是我最近经常画的一个图。第一个是知识，因为它是常识知识的表示，你先把知识做到头。知识能力做到头以后，我们还天天纠结知识，它已经饱和了。像一个人，当知识满载了，你想干什么？肯定想跟外界交互。早期第一件事就是要跟外界交互，要做 Agent。

GPT-4做了一个很简单的突破，就是调用工具。我为什么调用工具？其他主要是知识类，调用工具才跟外界有了交互。但光靠这么几个方式远远不够。要做更复杂、更多事情，Coding 更本质，必须把 Coding 能力提高，因为 Coding 是跟外界交互最本质的东西。

课堂问答（二）
Kaplan Scaling Law 的符号与实验设置
2020年 OpenAI 写了《Scaling Laws for Neural Language Models》。OpenAI 在那个时代做了很多贡献。Kaplan 当时是约翰斯·霍普金斯大学的教授。他原本做量子场、弦理论，后来做了 Scaling Law。有人觉得这太厉害，但也不是完全从零开始。2017年百度已经有人研究深度学习里的缩放规律；再往前，2012年 AlexNet 时，Ilya 就提出一定要做大，只是当时没把 Scaling 讲得那么明确。Dario 也在百度待过，我想应该也受到一些 Scaling 思路的影响。到 OpenAI 后，他和 Kaplan 等人一起做了这篇论文，所以课件写 Kaplan with Dario。
Scaling Law 并不是说只要“傻大”就有用。涌现能力告诉大家，扩大后能力会上升，无论看连续变化、间断变化，还是用 Loss 统一描述。而 Scaling Law 进一步告诉你，变化趋势是 Predictable，可预测的。并且要跨很大的尺度。100亿参数去预测200亿，意义不大，还不如直接训200亿。你必须能用100亿模型预测到1万亿时会怎样，这才是 Scaling Law 最本质、对研究最有帮助的地方。想想，训完10亿就能预见1万亿的效果，会有多大价值。
你可能说，得拿出来看数学、语文的 Performance。但刚才已经说，用 Loss Function 做统一，因为模型都在学广泛知识，任务维度相近，可以用共同的 Loss 观察。都是无监督学习，任务也类似，所以对比 Loss。这种大一统是大模型很美妙的一点。Scaling Law 给出三个重要结论，第一个是计算量增加。

模型、数据与训练步数的 Scaling 关系
由这些关系整理出 Scaling Law 公式。模型变大，数据和计算也要增加，不能只增加其中一项。但 Kaplan 的结论是，数据可以亚线性增长，什么意思？直观理解，比如参数增加10倍，数据也许增加5倍就够了。先强调，这是 Kaplan 当时的结论，后面会看到修正。第二个关系是 Training Steps，也就是训练步数与 Loss 的关系。
看这两张图，横轴是 Token 数，也就是训练数据规模，不同曲线代表不同参数量。数据变多、模型变大，Loss 更低。把模型放到同一维度，只比 Loss，会选哪个点？先训练三四个点，再拟合曲线，就有可能预见继续训练、继续扩大时的性质。这是研究中“打点”的意义。
另一张图横轴是 Training Steps，颜色代表不同参数量。同样训练步数，参数更大的模型 Loss 更小。图给人第一个感觉是，增加 Model Size 能降低 Loss。
第二个感觉是，模型增加得多，数据不必增加得一样多。但现实中大多数情况是什么？我有1000张卡、两个月时间，到底训多大？也就是说 C，计算预算，是固定的。这里几个符号解释一下：N 是参数量，D 是数据量，L 是 Loss，C 是计算量。通常只有1000或2000张卡、两个月，所以面对的是恒定 C，而不是可以无限增加的 C。

Kaplan 的计算最优分配
根据前面的公式，可以算固定预算怎样分配。Kaplan 对最优参数量给出的指数约0.73，还有 Batch Size、训练步数和数据规模之间的关系，不能只盯参数。按 Kaplan 的配方，要把模型做得很大，数据不必同比增加，它是亚线性的。后来 Google 的 Chinchilla Scaling Law 又调整了系数。
大家常听到“一个参数对应20个 Token”，就是后来广泛使用的1∶20口径。早期配方给的指引更多是增大参数，从后来的视角看还有问题。GPT-3 是1750亿参数，约3000亿训练 Token，差不多1∶2。现在我们的模型，数据大约30T，参数约700B，比例是一比几十。Kimi 这次没公布训练数据量，我猜可能也是几十T、30T左右，注意这是猜测。如果按2.8T参数和30T数据算，大致是1∶10。这是不同版本的选择，记住这些比例，等一下再看。总的来说，模型扩大通常能降低 Loss；Scaling Law 最重要的启示，是能预测模型往哪个效果区间走。

课堂问答（二）
通过小模型预测大模型表现
现在要分析模型精度很难。给你两个模型，问哪个好、哪个差，分析一周都未必能得到结果。你只能跑一些问题，但可能被 Overfit，结果也不一定可靠。长尾范围很广，很难充分测试。做模型的人如果都不能有效评测，怎样训练？Scaling Law 提供一条路：在小 Scale 调架构、调数据配比，先训4B、8B、16B，画出一条曲线，再预测1000B时可能是什么效果。
甚至预测10T。先说，不一定准确，但 Roughly 有用。GPT-4 的图也是用前面几个点拟合，再预测最终规模，计算量相差多少？相差1000倍。用约千分之一计算量，预测 GPT-4 训完后的 Loss，是一个非常优美的结果。所以 Kaplan 等人的工作对后世影响很大，让参数、数据、Loss 真正能被数学公式化。
原来做机器学习，经常拿一个模型，调整数据配比扔进去跑，再看最终数据集结果。因为不知道模型训出来会怎样，只能先试。结果不好，就做 Error Analysis，拿错误样本看原因，再调样本、调特征，扔回去继续。现在有了系统指导：应该怎样训、怎样配比，以及可能得到什么结果。原因也是成本结构变了。原来主要成本在设计算法，跑一次无所谓；现在大部分成本在真正跑那一次，所以必须事先预测。这是非常重要的改变。参数和计算之间的比例也值得仔细思考。

训练计算量为什么约为 6ND
每个 Token 对应算力成本，最后是一笔经济账。训练计算量跟参数、数据规模大约是 C≈6ND。为什么6ND？每个 Token 的前向计算，主要矩阵乘粗略是2N，D个 Token 就是2ND。Backward 要算梯度，包括对应权重梯度等，粗略是前向两倍，即4ND，所以合计6ND。先忽略 Embedding 等部分，这是一个总计算量的粗略公式。

Chinchilla 寻找最优参数与数据的三种方法
看 Chinchilla 左边的图，每条曲线都固定了计算预算。纵轴是 Loss，横轴是参数量。模型从小变大，Loss 会先降后升。这合理吗？参数过大、计算不增加，相当于没训练充分，Loss 反而高。所以固定计算预算时，实际上要选曲线最低点，也就是最合适的 Model Size。不同预算下都做这件事。把各条曲线的最低点连起来，就是最优选择的前沿。中间和右边展开这个结果：横轴是计算量，中间纵轴是参数量，右边纵轴是训练 Token 数。
它们也能看到 Scaling Law 的规律。这是2022年 Google 的 Hoffmann 等人发表的 Chinchilla 论文。左边有一组曲线，中间、右边各有一条关系，三者一起给出启示。要做全局优化，可以把它们放进同一个 Loss Function。里面 E 可以理解成不可约的熵下限。前面说的统一维度，就是把这些模型的训练都放到 Loss 上看。Loss 越小越好。如果数据和任务类似，模型做的事情就相似。刚才有人问 Tokenization 不同怎么办，如果你的 Tokenization 不如另一种，那理论上应该使用更好的。全世界大模型的训练和学习，某种程度上变得统一。

课堂问答（二）
公开人类文本的数据供给约束
问题就变成，在什么阶段 Scaling 什么东西。Pre-training 还有一个问题：数据上限在哪里？看图里的这条数据增长线。人类数据不可能一直按指数增长，它增长比较缓慢。2024年 Ilya 拿十年最佳论文奖，在 NeurIPS 做报告，很多人引用他“Pre-training 要到头了”这类表述。为什么？人类数据快用完了。有人又据此说不该训练更大模型，但他并不是简单表达这个意思。模型不断扩大，消耗数据越来越快。你看图里2026年附近，就开始接近这个约束，而人类数据增长慢，往上增长也比较平缓。
我原来估计人类文本大约100万亿 Token，也有人估计300万亿，总量终究有限。但还有合成数据。现在国内 Kimi、我们、DeepSeek、千问等，很多仍是在30多T的数据体量。有的到三四十T，有的到54T、55T，离300T这样的总量还远，继续扩大数据仍有空间。你可能问，为什么不一下扩大到100T？看 C≈6ND，D 增加，计算量也大幅增加，目前还可能撑不住。

重复训练、数据质量与合成路线
第二个方向是提高 Quality。已有数据能不能重复用，再多过几遍，也有很多值得计算的问题。重复以后，Performance 能不能继续提高？有人研究后发现，重复 Token 仍能让 Loss 下降。如果 Loss 下降还有意义，那么重复也有价值。第三条是合成数据。但不能随便让模型写一堆数据直接扔进去。
