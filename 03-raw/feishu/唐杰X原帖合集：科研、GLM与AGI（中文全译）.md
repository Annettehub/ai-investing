近期思考：
转向长程任务

转向长程任务
今年最可能出现的突破，将发生在长程任务上。我们正走向这样一个阶段：大语言模型（LLM）通过与智能体环境互动，学会完成持续时间更长、更加复杂的任务。这或许才是大语言模型真正的价值所在。以网络安全为例，想象一个持续搜寻软件缺陷和漏洞的模型。听起来像是一个搜索过程，实际上却是模型在学习专业黑客的高阶直觉与方法论。与人不同，人工智能可以全天候运行，不会疲劳。它有可能以高得多的频率发现可利用漏洞，并在 HackerOne、BugCrowd 等平台领取赏金。听起来很有趣，但从根本上说，这是一场会取代黑客的革命。如果连黑客都在被“颠覆”，对普通程序员的影响就更可想而知了。
从一人公司到无人公司

从一人公司到无人公司
建立在长程任务能力之上，自主智能体系统（AAS）将不可避免地成为下一个前沿。去年，我们还在讨论“一人公司”（OPC）的兴起，没想到这么快就迈向了“无人公司”（NPC）。这是一个有些讽刺的转折：在这个新的生态系统里，我们最后可能都成了 NPC。
用工程实现看似不可能的事：记忆与学习

用工程实现看似不可能的事：记忆与学习
要实现上述愿景，我们必须解决三个技术支柱：记忆、持续学习和自我判断。
我过去以为，这些能力需要巨大的范式转变和多年的研究。然而，技术与应用两端的压力都如此强烈，以至于我们看到这些能力正通过巧妙的工程“技巧”涌现出来。
记忆：长上下文窗口（100万 Token 以上）和 RAG 已经在很大程度上弥合了差距。
持续学习：真正的持续学习仍然困难，但模型发布周期正在缩短。全球模型按月更新，国内模型也在追赶。如果到明年能做到每周更新，实际上就会起到持续学习的作用。
自我判断：这依然最难捉摸，不过 Opus 4.7 等模型已经展示出初步的自我纠错与判断能力。
自我进化的终局

自我进化的终局
最困难、也最有前景的路径，是自我进化。当前这波浪潮异常凶猛。我怀疑 Claude 这类模型可能已经达到了自我训练的基本门槛：自己写代码、自己清洗数据、自己生成合成数据，再用这些数据训练自己。这可能会“浪费”一些算力，却节省了最宝贵的资源：人力与时间。在大语言模型时代，速度就是一切。快速迭代，才会造成领先者与跟随者之间的认知差距。传闻中 Claude 明年将部署的200万芯片集群，很可能就是专门用来做这件事：模型自主训练自己。
技术小结：
100万 Token 上下文：必要的基线。
记忆与持续学习：前提条件，很可能先通过“巧妙”的工程手段解决。
驾驭环境：突破点。
自我判断：临界点。
完全自我训练：终局。
重新定义 AGI 与行业

重新定义 AGI 与行业
如果这就是通向 AGI 的道路，那么 AGI 应当被定义为全人类集体智慧的总和，而非仅仅一个人的智慧。它必须具有创造像“相对论”这样深刻成果的能力，达到 Hassabis 所提出的标准。
在这一转变过程中，每一个应用都需要重构为 AI 原生应用。实际上，我们甚至可能超越“应用”这一概念本身。最大的挑战会是对操作系统本身的重构。未来，你看到的不会是传统桌面，而是一个 LLM 操作系统，应用将“按需生成”。这挑战了已有80年历史的冯·诺依曼架构，也意味着整个计算机科学行业的全面颠覆。
不可逆的浪潮

不可逆的浪潮
从完成长程任务到完全自主运行，安全、金融、法律、电商等每个行业都将被重塑。最近不少朋友联系我，问企业该如何转型，跟上人工智能的步伐。但真正意识到这一不可逆过程已经开始的人，仍然很少。在这股巨大的技术浪潮袭来时，我们必须准备好行动，也必须开始严肃思考如何对它进行监管。

关于规模法则的思考

关于规模法则的思考
扩展规模，但不只是扩展参数。现在每次模型发布，最后都会落到同一个问题上：有多少参数？这个问题不能孤立地回答。只有同时考虑另外三件事，参数量才有意义：你有多少数据、准备把算力花在哪里，以及谁会在什么条件下运行这个模型。
这个领域为弄明白这件事付出了代价。Kaplan 等人在2020年拟合出的一个指数告诉大家，参数应该比数据增长得更快，大约是2.7∶1。整个行业照做了：GPT-3、Gopher、MT-NLG。Hoffmann 等人在2022年重新对400个模型进行了实验，发现计算最优配比更接近每个参数对应20个 Token，而且在计算量充足时，两者应当以相同的速度增长，而不是越拉越开。早期拟合中的误差，会随着计算量每增加一个数量级而累积，因此那一代规模最大的模型，资源错配也最严重。回过头看，万亿参数那一轮，是整个行业一起走进去、随后又折返的一段弯路。
Chinchilla 也并非终点。它优化的是只训练一次、然后接受评估的模型所需的训练计算量。如今，一个模型每天会被调用数十亿次，推理占据了全生命周期成本的主导。把推理纳入优化目标，最优解就会转向更小、但训练时间更长的模型，也就是有意进行超额训练。Llama-2-7B 和 Gemma-2-9B 正是在这样做，它们每个参数大约分别对应290和889个训练 Token。
稀疏性又一次改变了目标。在 MoE 模型中，必须区分两个量：总参数量大致决定模型能装下多少东西，包括知识、事实和长尾信息；激活参数量与有效深度，则大致决定它能思考多远，在推理链断裂之前能走过多少个因果步骤。稠密模型的20∶1比例不能直接照搬。而且，这个比例根本就不是一个固定数字：Roberts 等人在2025年发现，最优的每参数 Token 数取决于任务，记忆任务更偏好更多参数，推理任务更偏好更多数据。对 MoE 的后续研究观察到，在固定 TPP，即每参数 Token 数的情况下，进一步增加总参数量反而会损害推理，而增加激活的专家数量，则能稳定地改善推理。
这对我们正在构建的目标很重要。寻找漏洞不是一个检索问题。它不是来自记住了更多 CVE，而是来自把一条20步的推理链走到底，并且始终不丢失线索。这种能力不在总参数量里。
这就回到了此次发布。总参数量似乎在某个阈值之前都很重要：要足够大，能装下世界。在那之后，新增能力来自扩展其他方面：每次前向传播的有效深度，尤其是后训练。GLM-5.3 就是我们针对这一判断开展的对照实验。与 GLM-5.2 相同的基座、相同的架构、相同的总参数量和激活参数量，用一个月扩展长程任务环境与强化学习。收益并不微小。扩展规模有不止一个旋钮。这次我们转动后训练旋钮，因为它还有最大的余量，而不是因为其他旋钮已经转到底。基座模型大小、预训练数据、每次前向传播投入的计算量，都仍然在考虑范围之内，我们会逐一回来继续探索。这次实验告诉我们，所有旋钮不必同时转动，而下一步最值得转动的旋钮，往往不是上一次最值得转动的旋钮。我们还没有结束规模扩展。下次，也许是中期训练、预训练，乃至更多方向。

两周。
GLM-5.3-Flash 从首次在国产加速器上成功运行，到承接全部生产流量，只用了这么长时间，期间端到端吞吐量提升至基线的3.2倍。
我一直在想的是，其中许多工作是谁做的：一个由 GLM-5.3 驱动的基础设施智能体。
一个模型，在帮助优化为它自身提供服务的系统。
条件很艰难：内存与互连带宽有限，100万 Token 上下文，多模态请求，以及尚不成熟的软件栈，有些内核根本不存在，文档往往只能靠猜。每一项优化都是取舍：用计算换内存（ReplaySSM），用通信换内存（节点内张量并行），用精度换容量（INT8/FP8/BF16 混合缓存），用解耦换调度自由度（编码、预填充、解码分离）。
但最重要的经验，并不在于某个单一优化。
当智能体卡住时，很少是因为它不会写代码，而是因为它不知道表现为什么变差了。
“吞吐量下降20%”告诉你有东西出了问题，却没有告诉你是哪一层、哪一个假设出了问题，或者下一步该测试什么。用强化学习的语言来说，这是带有信用分配问题的稀疏奖励。而一个要运行数小时的端到端基准，会让探索慢得令人痛苦。
资深工程师通过头脑中隐含的过程奖励来解决这个问题。他们知道什么时候该看时间线，什么时候该运行微基准，什么时候该比较某一层的输出。
我们把它明确地表达出来，称之为密集反馈：智能体可以直接调用的分层验证接口。
正确性反馈：计算得对不对？
系统行为反馈：时间花在哪里？
性能反馈：哪种方案胜出，在什么条件下胜出？
每一种信号都必须是局部的、低成本的，而且可以客观验证。
智能体发现了三件事。
第一，KDA 的上下文并行路径存在精度漂移，而且会随序列长度增长。原因是连续状态矩阵合并中，TF32 舍入误差不断累积。修复现在已经合入 Flash Linear Attention 上游，PR #1180。
第二，KV 传输从未与 DeepEP 分发重叠执行。智能体跨越 Python/C++ 边界，沿着调用链追踪，发现节点内路径一直没有释放 GIL。修复后，传输开销从超过30%下降到不足1%。
第三，一个解码内核因为分块方式的缘故，把同一个归一化计算重复了四遍。智能体重构了它，使运行速度达到原来的1.71倍。这个思路来自它阅读 SGLang、FLA、DeepGEMM 中已有内核后提炼出的“优化骨架”。
必须明确边界：人仍然负责确定目标、搭建反馈环境，并审查每一项高风险修改。
但工程师的角色正在改变：从亲自解决问题的人，转变为设计反馈的人。
还有更深一层的意义。建立在真实基础设施任务上的分层、可验证反馈环境，恰恰是下一代模型训练最需要的。智能体完成的每一个任务，都可以成为其后继模型的训练场。
我们距离递归自我改进仍然很远。
但最小的闭环已经存在。
