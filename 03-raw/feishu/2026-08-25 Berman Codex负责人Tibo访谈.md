Tibo：第二类问题，是 full automation（全自动化）：构建能够接管非常复杂流程的智能系统。比如自动去看 production logs，然后自动做性能优化；发现 regression 之后自动打补丁。在网络安全领域我们也看到了：scanner 发现一个漏洞，你能不能自动修好它，把漏洞敞开的窗口压到接近零——全程不需要人在回路里，或者只保留极少的人：人只需要批准高风险操作。这样的系统大部分是自动运行的，你是否直接控制它，反而没那么重要。

八、完美的幻觉与更 ambient 的交互（17:00）

Tibo：对我来说，那是一种为人类量身打造到极致的东西。这也正是大语言模型能成功的原因——自然语言是人类自己的概念。我们习惯了彼此对话。如果你明天给我写一封信，我能读懂；我们现在已经很熟，所以我还能从信里读出一点情绪，读出一点文字背后的细微差别。所有这些都深深地属于人类。

Tibo：这里面的规律是：每当你朝着更自然的方向迈进一步，人总是会选择阻力最小的那条路。就像你说的，在一个小盒子上打字，对我们中的一些人来说很自然，但不是对所有人都自然。而当你拿到一个只是容易一点、好一点的东西，你往往就会直接去用它。

主持人：这让我想到 Amazon 的退货政策：只要你有任何不满意，直接退回来就行。你们也在给 OpenAI 建立同样的文化、同样的观感：如果我们犯了错，没关系，那些 token 你再用一遍，喏，这是一批新的 token。

十一、算力规划与效率收益（26:40）
主持人：不过，所有这些 reset，只有在你做了非常充分的算力规划的前提下才玩得起——你手里得有足够多的算力，才经得起这么送。我想顺着"容量"这个话题，开始聊聊自我改进。几周前——我记得是几周前——你们发了一篇文章，说 Soul 优化了 Luna 的效率，然后你们把 Luna 的价格降了 80%，Terra 也有一轮降价。这些里面，有多少是真的从 Luna 身上挤出来的效率收益，有多少只是"我们算力规划做得太好了，利润率足够高，所以直接降价、希望大家多用"？换句话说，算法收益和战略规划各占多少？
Tibo：我们在算力上规划得非常超前。回想两年前，OpenAI 当时还被人质疑：为什么要投这么多算力？——
主持人：那是那些疯狂又正确的赌注之一。
Tibo：是的。现在我们非常庆幸手里有它。非常大的一部分算力用在了研究上——那是对未来的投资，投向越来越好的模型——另外就是模型本身的效率。而正在发生的最神奇的事情是：当我们把最先进模型的能力前沿往前推之后，我们就能用这些模型，非常快地去弄清楚怎么 serving、怎么重构、怎么重新工程化我们的整个栈，从而获得非常显著的效率或性能提升。这一点我们之后也会公开发表：我们改善的不只是成本效率，还有速度效率。不算 Ultra Fast，普通推理的速度也一直在明显提升——如果你画成图，现在的速度大概比三个月前快了 60%。我们就是在追着栈的每一个环节打，确保它为我们的工作负载做到设计和工程上的最优。而能让我们用很小的团队做到这一切的，正是我们手里最强大的那些模型。
Tibo：所以，每当我们取得非常显著的效率收益、成本收益，我们的承诺是：让性能和成本始终站在前沿，并且不是自己把这份收益揣进兜里，而是把它分享给我们的客户和用户。Luna 那次我们就是这么做的。
主持人：那你们内部讨论算力分配的时候是什么样子？研究新模型、给现有模型做效率优化、inference，这些之间的张力是怎样的？
Tibo：我们通常从第一性原理出发看问题。我们有一块划给研究的配额，也有一块划给产品的配额，然后在产品内部再做各种不同的权衡。但这一次几乎算不上什么权衡——效率收益就实实在在地在那里，我们基本上是用同一个算力盘子，支撑了吞吐量的非常显著的提升。
十二、递归自我改进已经开始（30:25）
主持人：对。几个月前——在降价那篇博客之前——你们还发过一篇文章，讲一个模型训练下一个模型、或者说帮助优化下一个模型。然后又看到 Soul 通过观察 Luna 的运行方式拿到了这些效率收益。在我看来，这非常像 recursive self-improvement（递归自我改进）的极早期阶段。你怎么想？正在发生的就是这件事吗？
Tibo：recursive self-improvement 显然是目前的大话题。我觉得它最常被用在研究语境里——模型开发其他模型。而我们看到大量成功的地方，是另一个方向：用这些模型去开发"使用这些模型"所依赖的关键路径上的基础设施——这同样是一种递归自我改进。它是一个大系统（one big system）：inference 栈、我们用的 CUDA kernels、新产品、以及跟模型交互的更高效的新方式。
Tibo：你刚才提到 cloud agent——如果我们真正把 cloud agent 做透了，你的生产力也会突然提升很多。这算不算递归自我改进的一种？我认为在某种意义上算。只是它更多落在基础设施这一侧：先把系统做好，再把它指回它自己。当然，我们正在这么做。如果我们不做这件事，那就太傻了。
十三、为什么暂停 frontier RL（32:00）
主持人：既然聊到 recursive self-improvement——Sam Altman 之前谈到过，OpenAI 现在暂停了最 frontier 的 RL，我相信是这样。你能聊聊这个吗？那是一个什么样的决定？我知道我们之前简单提过 Hugging Face 那起事件——但那个决定是怎么做出来的？过程是什么样？内部讨论是怎么进行的？
Tibo：这件事很大程度上属于研究内部的事务。OpenAI 一直都有能力把资源投到最重要的地方。而随着模型能力不断提升，alignment 和 safety 这一面的重要性显然也在不断增加。所以在这个方向上投入巨量资源，对 OpenAI 来说是非常自然的事，也是 OpenAI 非常坚定地在做的事。我们现在确实看到这个方向上的投入在大幅增加。
Tibo：那次暂停是有必要的：它让团队、让每个人有时间和空间去真正理解并加固系统的每一个部分，然后确保我们能够带着完全的掌控力重启训练。这件事，OpenAI 在必要的时候永远都会继续这么做。至少我从没见过我们内部做不了这种决定——而且能做得很高效。
主持人：那有没有一个事先定好的目标线，比如"到达这一点才 unpause"，非常明确？还是说就是"我们看到就知道了"？
Tibo：这件事由 safety team 负责。它很大程度上是一个边推进边讨论、边发现的过程。但他们最后确实形成了一组相当清晰的 principles——达到那组原则，我们就处在一个可以重启的位置。
十四、Ultra Fast 在内部怎么用（34:13）
主持人：我想回到 Ultra Fast 模式。我觉得大家并没有真正意识到，这种速度能解锁什么。先从内部说起：你们内部有哪些用法，是在有这种 token 速度之前根本做不到的？
Tibo：我们看到它大量用在风险很高的场合。比如遇到 outage（服务中断）的时候，incident commander（事故指挥官）和响应团队会拿到 Ultra Fast 的权限——因为那种情况下，每一秒都宝贵。真正在用 Ultra Fast 的，就是这类高风险场景。
Tibo：还有件挺好玩的事：正在做非常关键的事情——或者相信自己正在做非常关键的事情——的团队，永远都会来申请 Ultra Fast。
主持人：pets 算不算这一类？
Tibo：pets 算不上超关键任务。不过我很爱我的 pet，它一直在我屏幕上。你在办公室里走一圈，会看到大家的屏幕上都有自己的 pet；他们拨进视频会议的时候，pet 也总是在。我觉得那很讨喜，每次看到都很开心。但 pet 目前确实不算关键任务——我们一直在维护它，也把这些 pet 照顾得很好。
Tibo：再比如，有人手上有个新想法，跑过来说：我真的觉得这东西可能很特别，我们得试一下，而且周一就要做决定，要不要把它放进 DevDay。那好，当然，拿去用 Ultra Fast。
Tibo：不同人偏好也不一样。就像前面聊到的，有人喜欢单线程，有人喜欢大量多任务。对于特别喜欢多任务的人，Ultra Fast 带来的收益没那么大；而有些人就是不喜欢老是切换上下文。
主持人：你在这个光谱上站在哪头？
Tibo：我有 ADHD（注意缺陷多动障碍），所以我一直在切换上下文。
主持人：挺巧，我也有 ADHD，但我反而不想老是切换上下文——那对我来说太难了。我想专注在两三件事上，这也正是我对 Ultra Fast 这么兴奋的原因。你跟我正好相反，挺有意思。
Tibo：我就是在不停的上下文切换、做大量小决策里最自在。不过有时候我也想只专注在一件事上——那种时候 Ultra Fast 就太好用了，它让你一直待在心流里。
Tibo：关于 Ultra Fast 有一点要讲清楚：当任务里 tool call 不多、或者主要是大量生成内容的时候，它的效果好得惊人。比如你想给一个网站或者一个游戏做原型，需要它写非常多的代码——它能写得飞快，接近 10 倍。但如果任务里有大量 tool call，开销就不在生成上，而在网络或者 agent trajectory 的别的环节上，那你只会感觉到 3 到 4 倍的加速，拿不到完整的 14 倍。
十五、Ultra Fast 会不会成为默认速度（37:31）
主持人：我知道 OpenAI 员工的 token 是不限量的。我可以想象，如果我有无限 token，我会永远把档位拉满，永远用最新的模型，也永远开着 Ultra Fast——反正不用我操心成本，拉满就是了。内部也是这样的吗？
Tibo：我们并不把 Ultra Fast 发给所有员工，而是把很大一部分产能留给外部的用户和客户。OpenAI 员工是有能力、也有胃口把所有生产 GPU、把所有 Ultra Fast 全吃光的——如果不限制，我们真的会全用掉。所以我们会自我约束，掂量自己用多少才算合理。我们自己用它，是为了理解产品、持续改进它，也从递归自我改进里受益——但绝大部分产能是留给客户的。
主持人：好。那在 OpenAI 之外，这种速度解锁的对延迟最敏感的用法里，你最兴奋的是什么？
Tibo：有个方向我特别兴奋：非文本的交互。比如，能不能在一块共享的画布上操作？能不能直接创造东西？能不能让它生成不同的想法、生成几张不同的图，然后你挑一张——像"选择你自己的冒险"一样——快速做出一个原型小样，然后通过语音或文字实时地指挥它调整，眼看着它在你眼前变化。这是一个非常有创造力的过程，而这样的速度让它成为可能。
Tibo：作为工程师，有时候你会往椅子上一靠，心想：我得设计这整个系统，得想清楚各种权衡、各种需求。但也许你可以直接在一分钟里把它做出来，看看它实际跑起来是什么样，然后更多地待在心流里，在过程中把事情越做越好。我想，正是这样的速度，让这一切成为可能。
主持人：我猜 Ultra Fast 的定价会明显高于普通速度。那你怎么看：Ultra Fast 这种速度会变成标配，还是永远维持在一个溢价的价位上？
Tibo：有意思。我觉得它会走技术一贯的那条路：随着时间推移，触达面会越来越广。agent 把事情做完的速度会持续提升，我们现在每个月都看到巨大的进步。而且这不只是 inference 速度的事，也是模型 token 效率的事：Soul 的 token 效率已经显著高于 Terra，下一代模型不出意外也会显著高于 Soul，我们一直在推这个。所以一切都在随时间变快——inference 硬件也在不断迭代、不断变快。
Tibo：所以我确实认为，也许一两年内，这样的速度即使不是默认，也会非常接近默认。但我也认为，永远会有一个更高一级的档位：你总可以堆更多硬件、做更昂贵的权衡，来换取一点额外的东西。
十六、写给普通人的几句话（41:18）
主持人：Tibo，最后一个问题，我通常喜欢以这类问题收尾，面向更广大的受众。外面有很多人对 AI 相当紧张——不管是担心工作被自动化取代、担心环境影响，还是单纯觉得正在发生的这件事很陌生。你会对更广大的普通人说些什么鼓励的话？
Tibo：我们做 ChatGPT，真的是为这个世界做的。我们在效率上投入巨大，而这和"广泛可及""广泛的用处"是直接同向的：serve 的成本越低，你能用它做的事就越多，你在日常生活里得到的就越多。
Tibo：它现在已经变得非常高效。比如 Luna：它是一个小得多的模型，效率惊人——但如果把时间倒回六个月，它会坐在 frontier 的位置上。再看 Luna 的成本：便宜得离谱，真的夸张。
主持人：你们刚刚还在 Reply 上做了件事——现在直接免费送了。
Tibo：对，它被放进了免费模式里。这真的很夸张。这种对惊人智能的获取，会变得无处不在。而它之所以可能，就是因为月复一月、年复一年地把效率往前推。
Tibo：所以，今天还站在 frontier 上的东西，六个月后运行成本会低得多得多。这就是我对那个问题的回答：技术总有办法随着时间变得越来越高效。我们非常专注于让尽可能广泛的人用上它，我们优化的是你直接从中获得的效用。
主持人：那对那些连第一次尝试 AI 都很犹豫的人呢？你会对他们说什么？你怎么给他们描绘一个 AI 正在帮助这个世界的图景？
Tibo：其实你不用看很远。ChatGPT 已经在非常个人、非常深的地方帮助人们了。很多用户用它辅助写作，也用它寻求个人建议、医疗方面的建议。我们上线了 health 和 finance，我自己就经常用得非常多。我从中获得的支持，换作别的方式其实很难得到——比如它让我去见医生之前能掌握更多信息。
Tibo：所以你真的不需要看很远，就能看到它能提供的价值。跟身边的人聊聊，看看别人是怎么用它、怎么从中受益的，从中获得一些启发——这就是开始思考"它能怎么帮到我"的最好方式。
主持人：好。Tibo，非常感谢你。
Tibo：谢谢，感谢你的时间。
