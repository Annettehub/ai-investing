豆包要点总结

1. OpenAI与Anthropic在9月22日同日发布降价模型：GPT-6 Sol输入/输出价格均降50%（输入$2/百万Token、输出$10/百万Token），GPT-6 Luna降至输入$0.10、输出$0.50（分别降50%和58%）；Claude Opus 5.5输入/输出分别降至$4和$20（降20%），缓存读取价格从$0.50降至$0.20（降60%）
2. 模型竞争的计价单位正从"每百万Token"转向"每个成功交付的任务"。真实任务成本=输入输出Token成本+缓存和工具调用成本+失败重试成本+人工验证与返工成本，再除以任务一次成功并被接受的概率
3. Agent应用率先获得红利：编码Agent可处理更大代码库和更多测试循环，企业自动化平台把低价值步骤交给Luna，模型路由平台按任务难度在Luna/Sol/Opus/Astra间动态切换。标准架构趋向分层调度：廉价模型处理检索/分类/初稿，中档模型执行大部分工作，旗舰模型处理高难度决策和失败案例
4. 模型厂商面临价格与现金流夹击：OpenAI主动降API价格意味着收入增长越来越依赖调用量；Anthropic通过缓存、步骤数和输出Token压低任务总成本。价格变化三种情景：基准（价格降40-50%、任务量增2-3倍）、进取（低价模型让无人值守Agent进入生产环境）、压力（企业调用增长有限、开源模型追赶、供应商被迫反复降价）
5. 价格下降可能带来算力反弹（杰文斯效应）：一次AI任务成本减半后，企业可能把调用次数增加到原来的3倍，加入更多验证、监控和并行尝试，总Token和总推理时长继续增长。但需满足两个条件：新增调用量对价格足够敏感；模型能进入真实业务而非长期停留在试验场景

TLDR



OpenAI与Anthropic同日降价，模型竞争进入成本交付阶段

1. OpenAI与Anthropic在9月22日同时发布降价模型。GPT-6 Sol输入与输出价格均下降50%；GPT-6 Luna降至每百万Token 0.10美元输入、0.50美元输出。
2. Claude Opus 5.5的API价格较Opus 5降低20%，缓存读取价格降低60%；Anthropic称，由于模型使用更少步骤和Token，典型任务总成本下降约40%。
3. 模型竞争的计价单位正在从"每百万Token"转向"每个成功交付的任务"。真正成本还包括工具调用、上下文缓存、失败重试、人工复核和返工。
4. 价格下跌可能提高应用层毛利，也会压缩模型厂商收入。供应商能否把推理效率提升转化为利润，取决于新增调用量能否跑赢降价幅度。
5. 单位算力价格下降未必削弱GPU需求。若Agent开始承担长时间、高频率任务，总Token消耗和工具调用可能加速，形成类似云计算的需求弹性。



结论先说：前沿模型竞争正跨过一个重要节点

结论先说：前沿模型竞争正跨过一个重要节点。市场争夺的核心，从单纯提高能力上限，推进到用更低成本交付接近前沿水平的有效任务。
OpenAI和Anthropic同日降价，说明模型厂商已经开始主动压低"智能批发价"。这一变化对软件公司、模型厂商和算力供应链的影响并不相同：应用层获得成本红利，模型层面临收入压力，芯片和数据中心则要观察用量能否出现足够强的反弹。


一、两家公司同时压低价格



OpenAI推出GPT-6 Sol与GPT-6 Luna

OpenAI推出GPT-6 Sol与GPT-6 Luna，把Astra的部分推理、编码、计算机操作和对齐能力下放到成本更低的型号。
GPT-6 Sol每百万输入Token定价2美元、输出Token定价10美元，较GPT-5.6 Sol的推广价格均下降50%。
GPT-6 Luna输入价格降至0.10美元，输出价格降至0.50美元。与上一代0.20美元和1.20美元相比，分别下降50%和约58%。
GPT-6 Sol还提供105万Token上下文窗口，最大输出12.8万Token。模型可以在一次任务中读取更多代码、文档和历史操作，却也会增加缓存、注意力计算和信息筛选成本。



Anthropic同日发布Claude Opus 5.5，缓存读取价格降60%

Anthropic同日发布Claude Opus 5.5。输入与输出价格分别为每百万Token 4美元和20美元，较Opus 5的5美元和25美元降低20%。
更值得注意的是缓存读取价格，从每百万Token 0.50美元降至0.20美元，下降60%。缓存可以让模型重复使用已经处理过的代码库和长文档，避免每一步都重新计算。在长时间Agent任务中，缓存成本可能比首次输入更重要。


二、每Token价格已经不够用了



模型的真实单位经济性：每个合格任务成本

模型的真实单位经济性应写成：
每个合格任务成本
= 输入与输出 Token 成本
+ 缓存和工具调用成本
+ 失败重试成本
+ 人工验证与返工成本。
再除以任务一次成功并被接受的概率。



算例：10亿输入+2亿输出Token，GPT-5.6 Sol vs GPT-6 Sol

假设一个企业每月使用10亿输入Token和2亿输出Token。
按照GPT-5.6 Sol原价格，模型费用约为：
10亿输入Token×4美元/百万
+ 2亿输出Token×20美元/百万
= 8000美元。
使用GPT-6 Sol后，同样Token量约为4000美元。
但这仍只是静态测算。新模型如果减少重试和输出长度，实际任务成本下降会更快；如果企业因为降价而增加推理深度、并行Agent和验证轮次，总支出也可能回升。
Anthropic称，Opus 5.5单Token价格降低20%，典型任务总成本却下降约40%，原因是模型需要的步骤和Token更少，输出速度也较Opus 5提高超过30%。
这说明下一轮竞争会集中于有效Token。模型说得更少、工具调用更准、返工次数更低，其经济价值往往高于单纯降低报价。


三、Agent应用率先获得红利



聊天应用单次请求短，Agent需要持续读上下文、操作软件、调API、检查结果

聊天应用的单次请求较短，降价节省有限。Agent需要持续读取上下文、操作软件、调用API、检查结果和纠正错误，成本会随步骤数快速累积。
因此，本轮降价最直接的受益者包括：
编码Agent，可以处理更大的代码库和更多测试循环；
企业自动化平台，可以把低价值步骤交给Luna等廉价模型；
金融、法律和科研工具，可以增加验证与交叉检查；
模型路由平台，可以按任务难度在Luna、Sol、Opus和Astra之间动态切换。
未来的标准架构很可能是分层调度：廉价模型处理检索、分类和初稿，中档模型执行大部分工作，旗舰模型只处理高难度决策和失败案例。
价值也会从单一模型迁移至掌握工作流、客户数据、任务评测和路由系统的平台。企业更关心任务是否完成、结果能否验证，以及总体节省了多少人力。


四、模型厂商面临价格与现金流夹击



OpenAI把Sol价格砍半，只有单位推理成本至少同步下降或使用量大幅增长时毛利才能保持稳定

OpenAI把Sol价格砍半，只有在单位推理成本至少同步下降，或使用量大幅增长时，毛利才能保持稳定。
这与此前期披露的五年现金流压力形成直接联系。OpenAI计划投入巨额算力，同时主动降低API价格，意味着收入增长越来越依赖调用量、企业客户和高价值Agent任务。
Anthropic的策略略有不同。Opus 5.5单Token降价20%，同时通过缓存、步骤数和输出Token压低任务总成本。若技术效率提升快于客户价格下降，模型厂商仍可扩大毛利。
价格变化可以拆成三种情景。
基准情景下，模型价格下降40%-50%，任务量增长约两至三倍。模型收入继续增长，单位收入下降，算力需求保持扩张。
进取情景下，低价模型让无人值守Agent进入生产环境，新增任务量远超价格下降，推理收入和GPU使用量同步提高。
压力情景下，企业调用增长有限，开源模型继续追赶，供应商被迫反复降价，算力合同却难以及时缩减，现金流压力扩大。


五、价格下降可能带来算力反弹



市场容易忽略杰文斯效应：一种资源的使用效率提高后，总消耗反而可能增加

市场容易忽略杰文斯效应：一种资源的使用效率提高后，总消耗反而可能增加。
当一次AI任务成本减半，企业可能把调用次数增加到原来的三倍，并加入更多验证、监控和并行尝试。单次任务节省了算力，总Token和总推理时长却继续增长。
这对GPU、HBM和数据中心需求构成支撑，但需要满足两个条件：
新增调用量对价格足够敏感；
模型能够进入真实业务，而非长期停留在试验和聊天场景。
若企业仍需人工逐步复核，降价只能降低软件账单，难以创造数量级的需求。可靠性、权限控制和真值验证仍是Agent规模化的硬约束。
最强反方观点是，两家公司公布的成本优势主要来自自家评测，模型、推理强度、工具环境和任务成功标准并不统一，无法直接横向比较。
这个质疑成立。OpenAI和Anthropic都选择了有利于自身的成本能力坐标。Anthropic甚至明确承认，前沿模型之间的基准分差越来越难代表真实体验。
因此，当前能确认的是报价下降和模型效率改善的公司主张。模型能否稳定减少返工、降低人工审核，并在生产环境维持质量，仍需独立测试和客户数据验证。
当前判断将在以下情况失效：独立评测显示低价模型能力明显退步；长任务失败率没有改善；模型容量不足导致频繁限流；企业使用量对价格不敏感；或推理成本下降速度持续慢于对外降价。


后续硬信号



五个后续观察信号

1. GPT-6 Sol、Luna和Opus 5.5在独立Agent评测中的任务成功率与完整任务成本。
2. OpenAI和Anthropic的推理毛利率能否在降价后保持改善。
3. 企业客户每月Token用量、Agent任务数量及人工复核时间是否同步变化。
4. 低价模型能否带来新增生产负载，还是主要替代原有高价模型调用。
5. Sonnet 5.5、Haiku 5.5及其他厂商是否跟进降价，形成持续价格战。
