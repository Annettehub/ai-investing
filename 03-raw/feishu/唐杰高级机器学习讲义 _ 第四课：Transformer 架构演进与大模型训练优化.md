豆包要点总结
1. 训练超大模型时，稳定比什么都重要：NaN、数值溢出、loss 上升、checkpoint 丢失、训完不 work 等失败模式都是工程细节；"训明白"万亿模型的人极少
2. Transformer 是持续变化的框架：位置编码从绝对（APE）到相对（RPE）、RoPE（旋转位置编码，支持长上下文外推）；归一化从 Post-LN 到 Pre-LN、RMSNorm；残差演进出 mHC、Attention Residuals；MoE 从早期门控到 Switch Transformer、DeepSeekMoE 的细粒度专家与共享专家、负载均衡
3. Attention 加速与稀疏化：FlashAttention 通过减少 HBM 读写（IO-aware 分块、在线 Softmax）提速；稀疏注意力从 BigBird 固定模式到 NSA、MoBA、DSA 学习选择，再到 GLM-5.3 的 DSA+IndexShare；hybrid（linear+sparse）可能是主流方向
4. 优化器演进：AdaGrad→RMSProp→Adam/AdamW→Muon（正交化，作者加入 OpenAI）；学习率调度 Warmup、Cosine、WSD；Batch Size 与梯度噪音、critical batch；μP 超参数迁移；训练稳定性监控与数值精度（BF16/FP8/FP4）是成败关键
5. 未来方向：每模块都在被优化，因为模型越大每处都会出问题；正走向"让 AI 自己学习这些选择"的 AI learning AI by itself 时代；国产芯片明年有望大规模用于训练

大模型训练：架构、集群、监控与失败成本
看图的第二行，大模型训练既跟集群有关，也跟芯片有关。用 V100、A100、H100、B 系列，或者华为、海光等不同的卡，结果都可能有很大关系。同样的算法、同样的 setting 放上去跑，可能很快就出现一大片 NaN，整个训练挂掉，这就是所谓的“崩了”。
大家知道 NaN。浮点数溢出、数值变成零，再遇到除法或者传播，一个地方出问题，数值传给周围，周围又继续传播，很快就全爆了。这是一种“爆掉”，已经完全没法用了。
但这还不是最惨的。你可以找上一个 checkpoint，接着训练，想办法把它救回来。还有一种情况：训着训着，loss 不降了。上次讲过，我们追求的是 entropy floor，也就是“地板熵”。把世界上的知识表示出来，应该尽量逼近那个熵最低的点，可能达不到，但要不断往下走。
有时候训练过程中 loss 反而往上走，怎么调都没办法，这也是要爆。看到 loss 上升，你至少还会停下来想办法，从 checkpoint 重新开始，缩短步长，或者用其他办法，让它重新下降。如果还能接着降，也不错。
我上次说，真正把万亿模型训明白的没几个。“训明白”的意思，是在一个框架下把大量数据完整地走完。数据还可以过多遍，loss 还会掉。有些模型可能一遍都没过完就过不下去了，loss 不往下，只能 hold 住，停在那里。
最惨的还不是这个。最惨的是你看着 loss 还在降，似乎所有数据都跑完了，结果模型在真实场景下不 work。可能是 overfitting，也可能更诡异：前面看着都还可以，到后训练就不好使，怎么调都上不去。
有些 base 第一版 post-training 能上去，后面再加 RL、加各种方法，都没办法 improve。我们希望一个 base 能支持好几个版本的 post-training。比如训了 GLM-5，希望 5.1、5.2、5.3 都能用，这才是一个好 base。如果训完只能用一次，后面再也提不上去，这个 base 就没用了。这在技术圈里也可以叫“爆”。
所以我说，这像造火箭，是一个包含各种细节的工程。传统机器学习里难道没有这些问题吗？原来用梯度下降、随机梯度下降，似乎也没有这么多问题。为什么现在这么多？本质上只有一个词，学术上叫 Scaling，用老百姓的话说，就是“大”，太大了。
训练这么大的模型，必须并行，必须用 GPU。假如还用超算、用 FP32 或 FP64、double 类型去计算，后面很多问题也许就不存在。但要训这么大的模型，这样算的计算量太大，必须缩减计算量，还要并行化，所以要用 GPU。
用 FP8、FP4 必然有损，就得想办法避免这种损失。有时各种调优本身又会带来损失。还要 speed up：几万张卡一起训练，每节省一天，涉及的钱都很多。所以这些事情本质上都是“太大”带来的。
把火箭拆开，每一个零件可能都只是螺丝钉。一个螺丝钉差 0.001，好像没什么；但组装成一个火箭，各种小误差就会起作用。我们现在从头把这些事情逐个讲一遍。

绝对位置编码及其与输入向量的结合
这里的 10000 之类的数值是人定义的。之前说过，凡是人参与很多的定义，慢慢都会成为 AI 不喜欢的东西。AI 最不喜欢人在里面折腾它。但为了让事情一开始简单，我们总会先设一个常数，或者一个简单规则。
把内容和位置加起来，剩下的 Q、K、V 计算就很直接。每个向量里既有内容 embedding，也有位置 embedding，Q、K 相乘以后就会出现内容—内容、内容—位置、位置—内容、位置—位置，一共四项。
它的问题是，每个位置都有一个绝对表示。但一句话里，比如“清华大学是中国一所很好的大学”，重要的不一定是“清华”和“大学”排在第一、第二，还是第三、第四，而是“清华”在“大学”前面，或者前面几个位置。绝对位置没那么重要，相对位置更重要。
Absolute position embedding 不容易把相对位置刻画清楚。它要通过内容和位置的交互，间接 capture 两者的关系，并不是直接得到相对位置。
后来就有了 RPE。我直接刻画 i 减 j，也就是两个位置之差，再把这个差表示出来。Transformer 在 2017 年提出，2018 年 Shaw 等人的论文就在讲相对位置，其中有 Transformer 的作者 Vaswani。

Transformer-XL、T5 与 ALiBi 的相对位置设计
2018 年这项工作很快就把原来的绝对位置做了修改，在程序里也进行了改动，后面很多人才在应用中慢慢发现。随后有了很多相关研究，包括戴梓航、杨植麟等人做的 Transformer-XL。
Transformer-XL 是分块的，这时绝对位置不容易处理。他们未必一开始就只是为了做 RPE，但被迫需要设计相对位置表示。设计也比较复杂，把内容—内容、内容—相对位置等信息分成四部分来处理。

RoPE：旋转位置编码与长上下文
旋转位置编码的核心性质
今天讲的很多内容来自博客，今天大模型用的很多算法也先以博客发布。这跟技术进展的节奏有关。早期学术界先发 paper，再开源工具，然后推广很久，才慢慢有人用。后来大家等不及，计算机论文主要发会议，半年才能开会；再后来连半年也嫌长，就发 arXiv。到今天，连 arXiv 都觉得慢，发一篇博客，技术就算发布了。觉得值得，再慢慢写文章、再发表。
旋转位置编码也经历了这样的过程：一开始是博客，等到正式发表已经是几年后的事，发在 Neurocomputing。有些同学可能还不一定看得上这个期刊，但这项工作的影响很大。
它刚发博客时也没有那么火。后来 GPT-J、GPT-NeoX 用了，效果很好，在 X 上得到很多宣传。PaLM、LLaMA 后来也用了。LLaMA 改了不少细节，让它变得特别好用，因为早期版本也有一些 bug，不是那么容易使用。
它的本质思想是：不再在 embedding 上加一个东西，而是调整方向，让它旋转。从加法变成乘法，本质上是这么一个变化。但最初看起来计算和推导很复杂，后来通过改进、并行计算，让它变得很有效。
我们做 GLM-130B 时也用了旋转位置编码。那个时候还是百花齐放、百家争鸣，我们试过不同的 embedding 方法。后来发现，选择某种方法，不一定每一次都要冲到效果最优的那个点。训练自己的模型时，你会发现，很多选择首先是为了让整个 training 过程更 stable、更平滑。
假如训练过程能够平滑下降，总会更接近目标。平滑很重要，stable 更重要。

Normalization：效果、传递性与稳定性的取舍

Normalization：效果、传递性与稳定性的取舍
第二个内容是 normalization。最直观的做法，是做完一层运算、加上残差，再做 normalization，把数值归一化到一个区间。
我们用 FP8、BF16 训练时，数值区间有限，做加法以后，值可能变得很大，甚至爆掉。归一化让它重新回到中间的分布，只有两边很小一部分区间可能有损失。这是一个简单、直观的办法。
早期基本这样做。但很快就变了。原始 Transformer 写的是 Post-LN，后来放出的代码很快又采用 Pre-LN。两种形式看起来差别不大，实际上数值表现的差别很大。

Normalization：效果、传递性与稳定性的取舍
Pre-LN 与 Post-LN 的残差路径
在一种形式里，每次经过归一化；另一种形式里，梯度可以从头到尾贯穿，每一层都能传下去。Pre-LN 是先做 normalization，再把结果加回去；Post-LN 则是加完后再归一化。
有兴趣可以看一下熊瑞等人的论文，对 Pre-LN、Post-LN 初始化时的情况做了详细分析。当时他在微软实习，跟刘铁岩做这项工作。刘铁岩是清华电子系 94 级的，数学很好。我在微软实习的时候，他已经在那里工作，大家可以看看那篇文章。
首先，不是说 Pre 一定比 Post 好。不同模型里要试。我们 2021 年做文生图模型 CogView 时，用了所谓“三明治 normalization”，也就是两边都做，Pre 和 Post 都做，把它夹在中间。本质上还是那句话：让训练更稳定。
Post 的好处是每次归一化以后不那么敏感，数值都在区间内，但会影响梯度的传递性。Pre 的好处是梯度可以一直传过去，但也有风险：数值可能变大，误差也可能逐层传播、放大。
我们当时两边都做，在 CogView 论文里有这个设计。当时博士生丁明做了这项工作，本质上是让它更 stable。【此处提到他后来的去向，未清晰识别，待回听核对。】
做不同算法、用不同芯片、做不同实验时，很多时候都得试，不是说选了 Pre 就直接跑。每一种形式都有自己的优势。我们训练 GLM-130B，也就是 1300 亿参数模型时，选的是 DeepNorm。最重要的原因不是某一项效果最好，而是训练下来最稳定。
今天给大家讲的一个重要概念，就是训练超大模型时，稳定比什么都重要。

RMSNorm 与残差连接
RMSNorm：去掉均值中心化
现在用得更多的是 RMSNorm。原来的 LayerNorm 要减均值、计算方差，再做归一化。后来发现，在 rescaling 时，有些均值相关的计算可以去掉，不再减均值，直接按相应的数值做归一化，计算就简化了。
原来每次做归一化，要么减均值，要么按方差 rescaling。如果减均值对结果帮助不大，就把这一部分删掉。少了计算，速度就能提高，可能提高百分之五六十，甚至更多。到 2020、2021 年前后，RMSNorm 逐渐成为标配。
再看残差。网上经常讨论 2010 年以后计算机领域有哪些伟大的论文，何恺明、孙剑等人的 ResNet 就经常被提到。这个 idea 后来也用在很多地方。
上次说过，DeepSeek 做了 mHC，Kimi 做了 Attention Residuals，还有另外一些相关工作。这里另一项工作的名称收音不清，待核对。它们各自都有优点和缺点。

早期 MoE：门控与局部专家
回头看 MoE 最早的逻辑。大家学过概率模型、高斯混合模型、mixture model 吧？可以在高斯分布之上再加 mixture。
Mixture 的意思很简单：一个 input 分到不同的 expert，这些 expert 之间可以有 overlap，也可以没有。混合高斯就可以有 overlap。信息按一定分布分过去，比如 10% 到这里、20% 到那里、70% 到另一边，最后再 mixture 起来。
这就是早期的 expert model。那篇工作里的作者都很厉害，包括 Hinton、Michael Jordan。Jordan 早年跟 Hinton 有过研究经历，后来成为机器学习领域非常重要的人物。
早期 idea 就是一个 mixture model。它的好处，大家可以做一个简单证明：均值不变，同时可以降低方差，让结果更 stable。早期做的不是今天 Transformer 里的事情，而是把不同 information capture 得更准，降低 variance。

FlashAttention：减少 HBM 读写

FlashAttention：减少 HBM 读写
GPU 相关的存储层级，有 CPU 内存、GPU 的 HBM，以及 SRAM。这里展示的是 A100，它们各自有容量和带宽限制。片上存储很小，外面一层的容量可能是它的百倍、千倍，CPU 内存又可以做得更大，几个 T、几十个 T 都可以。但容量小的那一层，带宽反而很大，所以容量和带宽是反过来的。计算时，要把数据一层层 load 进去。关键是怎么让数据高效地参与计算。
早期 attention 的计算过程，大致是从 HBM 把 Q、K load 进来，算出 S，再把 S 写回 HBM；然后把它读回来做 softmax，接着再算输出。整套过程会多次访问 HBM，访存带宽就成了局限。

这也跟 kernel fusion 的思路相近。所谓 kernel fusion，就是把几个算子、几个操作融合成一个操作，减少外部读写，让它变快。这里也是把多次访存尽量变成更少的访存。

机器学习最简单的优化，说白了就是把参数调到最优。早期 machine learning 里，有一个参数 θ，迭代更新它，原来的 θ 再加上或者减去学习率乘梯度，就是标准的机器学习公式。

训练循环与 SGD 的参数更新
你可能觉得这些我们都会。但大模型时代的问题在于，优化器、learning rate、batch size、超参数、训练稳定性，以及跟 GPU 有关的数值精度，每一样都因为规模变大而变得重要。
原来在 PC、服务器上用 double 跑，可能不是什么大事。Learning rate 调低一些，多少总能收敛；实在不行，再跑一遍。但规模大了以后，budget 是有限的。
比如小模型本来一小时跑完，你程序写得不好，跑了一天，差十倍也可能就这样过去了。现在如果程序差十倍，本来两个月训完，变成两年。两年以后再出来，还有什么意义？这样的研究没有意义。
所以我们要拆解：规模大了以后，每个小细节应该怎样做。Batch size 也是一样。模型小时，可以把所有样本过一遍再算梯度；模型大了，不可能每次都这么做，只能 sample 一部分，但到底 sample 多少，又变成一个变量。

从 AdaGrad 到 RMSProp
AdaGrad：逐坐标的自适应步长
2011 年有 AdaGrad，它做的事情，就是把历史梯度考虑进来。
为什么考虑历史梯度？原来每一步的梯度更新，学习率 η 往往是人工定的。我以前写机器学习程序，会按循环次数，让步长越往后越小。比如开始设 0.1，后面降到 0.001，完全是人设的。每次梯度有多大，我并不知道。
AdaGrad 把历史梯度累积起来，放进更新式里，这是一个很早的改进。
test.jpg


从 AdaGrad 到 RMSProp
RMSProp：从累积和到指数移动平均
后来 RMSProp 对当前梯度和历史累积做了一个修正，到今天仍然广泛使用。这个 idea 甚至没有正式发表，最早是在 Hinton 的一页 lecture 里写出来，就对后面产生了很大影响。
AdaGrad 的累积方式很简单，在分母里放历史梯度的累积项；RMSProp 又调整了它的累积方式。

另一条最近讨论很多的路线是 Muon。现在也有人研究把 Muon 跟 Adam 结合，分别吸收它们的优点。我们最近招了一位从美国回来的研究者，也在做这两个优化器的整合。

一个重要结论是，参数规模与精度也有 trade-off。训练一万亿参数和两万亿参数，难道两万亿一定更好？不一定。如果两万亿用低精度，例如 FP8，而一万亿用 BF16，后者可能更好。另一边可能是在用更多参数弥补精度。
上节课讲 Scaling，核心是数据和 size。今天看整个训练过程，每个小细节都有可能影响结果，包括精度。每层激活、求和、梯度累积，都可以用 BF16、FP32、FP8，但每种选择都可能带来损失。
把所有梯度加起来，可能溢出。究竟在 FP32、BF16 还是 FP8 上溢出？每一点误差看起来可能不重要，累积起来又可能很重要。
