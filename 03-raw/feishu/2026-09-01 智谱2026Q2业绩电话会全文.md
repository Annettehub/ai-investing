首席执行官陈述（唐杰）

大模型从对话转向做事，coding是关键卡点
唐杰：各位投资者、分析师，大家晚上好，非常感谢大家参加 2026 年的中期业绩会。我简单介绍一下智谱的基本情况、我们最近的一些想法，并展望未来技术上的布局。
大家都知道，大模型发展已经有将近 10 年时间。从去年开始，智谱就意识到大模型已经从对话开始转向做事。我们也是国内最早开始在这方面布局的公司，将模型的 coding 能力进行了大幅加强。去年年中我们发布了 4.5，这是第一个在 coding 能力上做出很好效果的模型。今年以来，我们陆续发布了 GLM-5.0、5.1、5.2、5.3，5.0 这个系列都是在同一个基座上做的。

Scaling不止参数：深度、后训练、环境多维度加强
首先大家可能会问，scaling 是不是一定要把参数做得很大。第一，scaling 是通向更高智能的关键路径。今年以来，我们在参数基座的规模上、在后训练上、在环境上都做了大幅加强。简单地做大参数，并不是 scaling 的本质路径。在这方面我们想了很多，比如在做大参数规模的同时，还要让模型在深度上做得更深，例如通过 LoRA transformer 让模型在思考的过程中想得更深，我们最近正在做这方面的工作。另外，在后训练上也可以做很多事情，使模型在后训练上做出很深的工作，因此我们在 5.3 上又做了很多工作，让模型在后训练上得到大幅加强。
同时，大家知道 coding 里面有很多不同的任务，如果把 coding 里不同的任务都进行加强，整个模型的能力会大大加强，所以我们在不同的环境上做了很多相关工作。大家看到 5.3 的效果一下子做得非常好，达到了一个 short 的 performance，达到了智能的上界。

基础设施普惠：国产卡+收购infra公司，OpenRouter调用量一度第一
另外，我们做模型更重要的是要让大家能用，不能用的模型存在很大的问题。所以设计模型时，我们不仅要设计模型的大小，还要设计模型的激活参数，同时思考模型的 infra，也就是基础设施让大家推理成本比较低，这样才能更加普惠大众。今年设计整个 GLM-5 的时候，我们把 infra 的能力大大加强。尤其是在当前各种卡都出现的时候——不仅有英伟达的卡，还有很多国产的卡——我们今年也借助了很多外部力量，包括收购了一个 infra 公司，把 infra 的能力大大加强，使得 5.1、5.2、5.3 这几个模型到现在几乎很容易让大家用起来，用量也非常大。到目前为止，在 OpenRouter 上我们的调用量一度达到了第一。同时，MaaS 平台在每一次模型发布后，调用量基本上都能成倍增加。这是我们今年整体的布局和基本情况。

未来布局：long horizon task、autonomous AI、完全自训练
对于模型研发公司来讲，核心还是做智能的上界，这又回归到智谱最本质的愿景。2019 年我们给智谱定义了唯一的愿景：让机器像人一样思考。直到今天我们还在探索智能的上界。探索上界不是简单地训模型，还要思考这个模型未来到底有什么样的智能、到底应该做什么样的事情。在下一步的布局中，我们有很多不同的思考。第一，今年年初我们看到 coding 已经变成大家都认可、广而周知的事情，我们思考在 coding 的基础上让模型做更多的事情。于是今年年初的 5.1 和 5.2，我们发起让模型做得更长的方向，叫 long horizon task，甚至提出了 autonomous AI，也就是让模型能够完全自治地做一件事情。
有了这两个能力之后，模型还需要做更多的事情。我们现在已经启动让模型完全自训练的研究：模型可以自己学习预训练、自己学习中训练、自己学习后训练、自己搭建 harness，让整个训练过程完全自主化。大家可能已经看到，我们最近在做 infer 优化的时候，尤其是这次 5.3 发布时在国产卡上做 infer 优化，已经借用了 infer agent，让 5.3 的 infer agent 自主修正我们在国产卡上的优化，使得效果大大增强。未来我们将在这条路上进一步发展，让它做得更强。
最后，在普惠 AI、让所有人用得起来的路上，更重要的是社会责任。一个模型的发布、让模型用起来，还需要有模型的治理和安全。我们也在不断思考，让模型在社会治理、社会安全甚至伦理上做得更强，所以我们最近也发起了社会治理相关的研究。也希望广大投资者、分析师能给我们更多建议和支持，让我们在未来探索 AGI 高地、探索让 AI 普惠大众的路上走得更远、走得更高。感谢大家。
董事长陈述（刘德兵）：战略聚焦与模型发展

上半年关键词：能力兑现——模型第一次被证明能独立把一件事做完
主持人：我们把接下来的时间交给刘德兵先生。
刘德兵：各位投资者朋友、各位分析师朋友，大家好。接下来请允许我把这半年的成果与思考向各位做一个完整的汇报。我先给这半年一个概括：如果说去年我们的关键词是智能上界，那么今年上半年的关键词就是能力兑现。模型第一次被证明不再只是工具，而是具有独立把一件事做完的能力，收入结构随之完成置换，模型的商业价值开始规模化的兑现。
第一部分，是公司在这个基础之上的战略聚焦和模型发展方面的思考。

公式：AGI商业价值 = 智能上界 × token消耗规模
第一，智能上界决定任务的边界，任务价值决定商业空间。今年 3 月的年度业绩会上，我们提出了一个公式：AGI 商业价值等于智能上界乘以 token 消耗规模。智能上界决定了模型能处理哪些任务、单位 token 能创造多少用户价值；更高的智能上界意味着模型能处理更高价值密度的任务，每单位智能对应更多的经济产出。Token 消耗规模反映智能被使用的广度和深度。同样一个 token，拿去闲聊或拿去修复一个生产环节的漏洞，产出相差几个数量级。因此，智能上界决定了任务的边界，而任务的价值决定了商业空间。Token 落在什么价值密度的地方，取决于模型能打开什么样的任务边界，而任务边界每上一级，市场空间就放大一个量级。

模型能力五阶段阶梯：Chat→coding→agent→co-worker→autonomous AI
第二，公司模型能力发展的五个阶段。我们认为，大模型能力的演进不是几条并列的产品线，而是一条只能按顺序走完的阶梯：Chat、coding、agent、co-worker、autonomous AI 五个阶段。Chat 交付的是一次性的回答，coding 交付的是一段可运行的代码，agent 交付的是一条被执行完的多步任务链，co-worker 交付的是一份可以被专业人士复核的工作成果，autonomous AI 交付的是持续运行的能力。每一级向上都有一个具体的技术门槛，门槛跨不过去，上一层的商业模式就不成立。从 chat 到 coding，门槛是结果可验证；从 coding 到 agent，门槛是长程规划与错误恢复；从 agent 到 co-work，门槛是可靠性达到专业人士愿意复核而不推倒重做的水平；从 co-work 到 autonomous AI，门槛是模型能否自己判断做得对不对。
报告期内，公司的重心处在阶梯的第二级 coding 到第四级 co-work 之间。公司已在网络安全、法律、金融、教育等方面展开尝试，其中网络安全进展最快，其余方向仍处于早期，尚未形成规模化收入。公司模型在 CyberGym 上取得了 84.5% 的成绩，超过了 Vibe 5 与 GPT 5.6；在 ExploitBench 上完成了 130 项任务，仅次于 Vibe 5 或 GPT 5.6。

持续最优轨迹：11个月6次迭代，智能指数32→60
第三，保持持续最优的模型轨迹，保持 SOTA。过去一年，行业对 SOTA 的理解正在被改写：时点榜单的领先不再是最重要的事，真正值得关注的是谁能以更快的节奏、更优的成本，持续把更强的模型推向市场。单点冠军只是转瞬即逝的点，持续最优才是一条不断向上推进的轨迹。GLM 系列在约 11 个月内完成了 6 次迭代，智能指数从 32 提升至 60，单任务成本稳定在 0.2 美元每 M 的档位；GLM-5.3 Flash 更是以 0.045 美元的单任务成本进入了智能的成本前沿。

GLM-5各版本定位：5.0打开长程智能，5.2旗舰长程，5.3后训练突破
其中，GLM-5 以 coding 为入口打开了长程智能，能力重点由代码生成延伸至系统理解、任务规划、工具调用与工程交付，推动模型从 web coding 走向 agentic engineering。编程方向已成为公司收入的主要来源，在 coding 中积累的长程任务能力也已在网络安全等方面得到迁移验证。GLM-5.2 是面向长程任务时代的旗舰模型，支持真正可用的 100万上下文，实测可承载项目级工程上下文，长程任务执行更稳定，工程规范遵循更可靠，开发场景成功率进一步提升，一次任务即可完成从需求到多端可部署产物的完整开发链路。
GLM-5.3 是智谱最新的旗舰模型，复杂软件工程与 Agent 任务能力全面进阶。它使用与 GLM-5.2 相同的基础模型，所有提升均来自后训练，但在复杂编程与长程任务方面表现更加出色。在 GLM-5.3 的训练中，我们进一步推进了任务环境的规模化训练，使训练任务不再只是传统的编程题，而是更接近专家在真实工作中承担的完整专业工作单元。同架构、同总参数、同激活参数，唯一变量是后训练规模，端到端完成率提升超过 50%。GLM-5.3 也证明 scaling 不止参数一个因素，而后训练是当前余量最大的那一个。

GLM-5.3 Flash：成本前沿，匿名上线6天62万亿token
如果说 GLM-5.3 代表当前的能力上限，GLM-5.3 Flash 则代表成本的前沿：面向高频、大规模、对成本敏感的调用，采用全新架构，专为极低成本设计。总参数 3200亿，激活参数 180亿，稀疏注意力与线性注意力混合，价格为 GLM-5.2 的 1/10，基准测试与实际应用均优于 GLM-5.2。发布前，它以匿名模型 ox-alpha 在 OpenCode 与 OpenRouter 上接受真实调用的检验，上线首日冲至 OpenRouter 榜首，并刷新单日 token 用量纪录；6 天调用总量超过 62 万亿，带动平台整体调用量提升超过 20%。

国芯国模：10万卡级国产芯片推理，成本下降80%
第四，在国芯国模上的进展。自年初起，我们将国产芯片纳入主力推理算力。GLM-5.3-Flash 是公司第一次在超大规模真实流量中，全面使用国产芯片集群提供服务的模型。芯片之间通过自研高带宽互联网络连接，整个推理引擎由 GLM-5.3 驱动的 Infra Agent 大幅加速，算子开发周期缩短一半。模型优化系统，系统承载模型，这个循环第一次在公司内部跑通了。结果是在同一硬件上与初始基线相比，端到端服务性能提升 3 倍。公司已经实现十万卡级国产芯片的规模化低成本推理，单位 token 推理成本较年初下降 80%。在全球算力供给持续紧张的条件下，这条路径意味着我们的成本曲线已经开始掌握在我们自己手里。

首席财务官陈述（肖涵）

收入结构质变：总收入9.54亿（+400%），API占比86.5%
肖涵：各位投资人朋友好，接下来我跟各位分享公司的财务业绩和业务发展的情况。
今年上半年，公司总收入达到 9.54亿元人民币，折合 1.42亿美元，同比增长接近 400%。比增速更值得注意的是收入构成的切换。上半年，开放平台及 API 业务的收入是 8.25亿元人民币，折合 1.23亿美元，同比去年上半年增长超过 27 倍，占总收入的比例由去年同期的 15.2%、去年年末的 26.3%，显著提升到了 86.5%。也就是说，站在今天，智谱的主要营收构成，已经基本都由开放平台及 API 业务来贡献。

ARR达16亿美元，激进口径超20亿
大家知道，在刚刚过去的这个月和上个月，我们发布的 GLM-5.2、5.3 和 5.3 Flash，带来了整个开放平台和 API 业务的一个历史性放量。截止 2026 年 8 月月末，我们的 ARR 已经达到了 16亿美金。这个 ARR 是按非常简单的年化月度收入去计算的，就是拿 8 月的收入乘以 12。当然我们也很清楚地知道，海外的前沿模型公司和行业内还有另外一种更激进的算法，是拿最近一周的数据直接乘以 52。考虑到整个 GLM-5.3 的放量，如果按这个比较激进的口径计算，我们最新的 ARR 已经超过了 20亿美金。

量价齐升：调用量+40倍，定价+101%
但我们觉得更重要的可能是 ARR 这个数字背后真正的驱动。我们非常欣喜地看到，今年以来智谱的整个收入增长，是一个相对比较健康的量价齐升。截止今年 8 月末，MaaS 平台 token 调用量较年初整体增长超过 40 倍，其中 Coding Plan 的调用量增长超过 23 倍；与此同时，整体的 API 平均定价提升了大概 101%。这充分证明了今年以来平台收入的历史性放量，是由模型能力为主要驱动，而不完全是由价格弹性驱动的。

毛利率大幅改善：从-0.4%到24.6%，亏损开始反哺研发
得益于上述量价提升，整体业务毛利率在今年也发生了大幅改善。开放平台及 API 业务的毛利率，从去年上半年同期的负 0.4%，到今年上半年的 24.6%，同比抬升了 25 个百分点；较去年全年（去年年末口径）的 18.9% 也抬升了 6 个百分点。
在研发上我们继续全力以赴，因为我们非常清楚地知道，模型的领先是一切的前提。2026 年上半年，整个公司的研发支出达到 21.31亿元人民币，约合 3.17亿美金。今年上半年公司的期内亏损大概是 20.72亿人民币，较去年同期减少了 12.1%；亏损率（期内亏损除以收入）较去年上半年收窄了 4.7 倍。经调整净亏损今年上半年是 19.64 亿，经调整亏损率较去年上半年收窄了 3.5 倍。所以可以很明显地看到，随着整体收入规模扩大，整个单位经济仍在快速改善。特别值得欣喜的一点是，今年经调整净亏损的数字（19.64 亿）小于我们的研发投入。这说明继去年年报以来，今年上半年业务贡献的毛利润，在初步覆盖掉管理费用、销售费用之后，已经开始逐渐反哺我们的研发投入。

收入结构三阶段演进：本地化部署→coding API→agentic/cowork任务交付
接下来第三部分，我再跟各位详实地分享财务数字背后的业务经营情况，大概从五个方面。
第一个方面，是整个收入结构的一个质变。今年上半年，开放平台及 API 业务的收入占比已经达到 86.5%。这背后其实不是我们主动设计的一个结果，而是模型能力本身的提升带来的一个自然演进。回顾公司整个业务发展的历程：我们从两年前最早单纯卖本地化部署的模型，到后来卖 API 的调用，再到卖订阅制的套餐，到今天卖端到端的任务结果。这样的演进历程，是随着模型本身智能表现提升之后，依次去解锁的场景和形态。随着模型能够独立完成的任务越来越完整，客户购买的东西本身就越来越靠近结果本身，用来计量收入的单位也随之发生改变。
回顾 2025 年以前的第一个阶段，公司主要耕耘本地化部署的业务。因为那个时候早期的模型尚不足以独立完成一件完整的工作，对于用户而言，购买的是工具，而工具需要被集成、被定制、被交付到自有的环境当中；叠加上数据安全、合规和自主可控的要求，本地化部署是当时企业采用大模型的一个非常自然的起点。到 2025 年年初以后，我们逐步进入第二个阶段，coding 的阶段。这个阶段非常代表性的一个特点是模型本身从知识驱动走向了任务驱动，编程能力的提升推动了整个 API 和订阅制 coding plan 这些产品的快速增长。公司在这个阶段，战略性地收缩了本地化部署模型的软件授权业务，转向持续提供可调用、可扩展、可以量化的智能服务。
到今年以来，我们更走到了第三阶段：agentic 和 cowork 阶段的同时到来，业务由模型的调用慢慢走向了任务交付。今年上半年，GLM 模型在 Agent 规划、工具调用、持续执行这些长程任务的能力上继续提升，业务也由 coding 单点的应用，向软件工程、网络安全、数据分析、复杂自动化这些高价值场景延伸，业务的方式也从卖调用进一步走向了销售订阅、销售端到端的任务结果这样一种模式。面向未来，cowork 正是这个阶段我们正在打开的部分：模型本身连接了企业的数据、工具和业务系统，嵌入到企业的采购、财务、客服、研发、IT 运维等多个环节，本身就具备理解需求、走到执行任务的前提，而企业的真实工作流又能够反过来成为模型可以学习的环境和数据。
在今年上半年的报告期内，公司已经开始尝试在网络安全、法律、金融、教育这些方向进行布局。进展上，目前在网络安全领域进展最快，其他方向诚实讲还在一个早期阶段，还没有形成规模化的收入。
把刚才讲到的本地化部署、coding 和 cowork 这三个阶段连起来看，其实是一条线。总结来说：模型每完成一次能力的跃迁，客户购买的东西就离最终的经济价值和最终的结果靠近一步，公司的收入结构也随之改写一次。这是第一个方面，从历史沿革的角度跟各位分享公司收入结构变化背后的根因。

Go-to-market：高价值任务做深，普惠层并行，API与Coding Plan并举
第二个部分，跟各位分享整个 go-to-market strategy 的拓展。今年以来，行业内非常关心除了模型本身在各种 benchmark 上的得分以外，越来越会关心模型能不能在智能和成本这两个维度上实现帕累托最优，这已经是行业现在最关心的话题。今年上半年我们继续沿着高价值任务场景做深做透的同时，本月也推出了 GLM-5.3 Flash 这个模型，其实就是希望证明前沿智能也能够进入到普惠场景。这次依托 10 万卡级以上的国产芯片集群，我们已经初步实现了超大规模的低成本推理。上个月月底，在算力侧迎来阶段性重要升级之后，我们向全量用户开放了 Coding Plan 的订阅，覆盖了 Light、Pro、Max 和团队版本，这是国内最早以订阅制交付的编程智能体能力的大模型服务之一。我们非常希望能在用 API 服务满足企业级需求之外，为中国的开发者们提供最好的订阅制编程套餐产品。从高价值任务到前沿智能与普惠层并行，从企业级服务到 API 与 Coding Plan 并举，我们的 go-to-market 策略本身就希望朝着更深、更宽、更均衡的方向去努力。

用户规模：740万注册用户，付费日活+603%，前十大用户调用+98倍
第三个部分，也是我们第一次跟各位非常详细地拆分分享：作为中国最大的独立开发者平台之一，我们 MaaS 平台上的用户规模、使用深度和用户质量大概是什么样的。截止 2026 年 8 月，智谱 GLM 平台的注册用户数已经超过了 740 万，较年初增长了 144%；付费日活用户数较年初增长了 603%；从收入的角度来计量，前十大用户对比年初的日均调用，本月的日均调用已经增长了 98 倍。这三个数字是层层递进的：我们构建了中国到目前为止最大的开发者平台之一，同时平台的用户总量在大基数上对比年初仍然有一个巨大的增长。也非常欣喜地与各位分享：就在刚刚过去的两个月，通过 5.2、5.3、5.3 Flash 这三个模型，我们从 6 月底 580 万的用户数量激增了 160 万，达到了刚才讲到的 740 万的体量。这说明进入长程任务时代以来，我们的重度开发者用户无论从基数上还是使用深度上，对平台的日均调用都远远超过此前 vibecoding 时代的真实工作流。
与此同时，平台上高质量用户群体也在日益扩大。截止 8 月末，在开放平台上年化贡献（ARR 口径）超过 10万美金、50万美金、100万美金、1000万美金、2500万美金、2.5亿美金的高质量用户群组，分别达到了 115 个、25 个、37 个、8 个、2 个和 2 个。这是我们关于用户规模、用户画像、使用深度和用户质量的分享。

算力乘数提升14倍，飞轮初步转动
第四个部分，是这一次我们也跟各位分享的一个新的概念，叫做算力乘数。这是近年来行业内非常关注的一个概念，在成本端体现的是大模型公司每投入 1 元算力（同时包括训练侧和推理侧的投入），所对应的开放平台及 API 收入这么一个比例关系。公司今年的算力乘数较去年上半年整体提升达到了 14 倍，也就是说整个算力供给的优化得到了极大的改善。这条曲线的改善其实来自于两头的原因：一头是单位 token 承载的智能在提高，单位任务消耗的 token 与成本在下降；每投入 1 元算力换回的收入不断增加，意味着模型从经济模型上而言，自我造血的能力在不断增强。智能的突破换来更大的 token 调用与商业回报，这些回报再投入算力与进一步的研发，进一步抬升模型的智能上界，这个飞轮目前已经初步转动起来了。

安全能力与模型能力同步增长
最后一个部分，是安全能力与模型能力的同步增长。我们非常清楚地知道，模型能力要想变成可依赖的服务，中间其实隔着一件事情：真实的世界能否信任它。我们的做法始终是坚持开源、开放与安全能力的同步增长。一方面，公司通过开源模型权重、MaaS 平台、Coding Plan 与全球开发者网络，让模型进入尽可能多的真实环境；另一方面，公司通过权限控制、过程监督、风险评估、漏洞披露与外部验证，来建立能力的可核查性。
以上两部分就是关于公司财务业绩和业务发展方面的介绍。最后关于未来展望的部分，我再交给智谱的董事长刘德兵。
未来展望（刘德兵）

从长程任务到自治系统：数小时工程任务→数天完整交付
刘德兵：在上半年，我们验证了模型可以独立完成一个完整的工作；在下一步，是让它承担一个完整的业务。围绕着这个目标，我们对未来有了一些判断，下面介绍一下。
第一个，从模型任务上讲，我们现在正在从长程任务往自治系统演变。今天的前沿是数小时量级的一个工程任务，而下一步是数天量级的完整交付。让模型在更长的周期里保持目标一致，持续地拆解任务、调用工具、与环境交互、修复错误、验证结果，同时从单一 Agent 走向多 Agent 分工协作，由模型承担完整的业务流程，从辅助工作走向执行工作。这一步的门槛不完全在智能本身，而在可靠性和可审计。模型要能在没人逐步检查的条件下干活，同时留下可复核的痕迹。

Scaling四因素轮换：基座规模/有效深度/训练深度/任务环境
第二点，能力方面，我们看到 scaling 从未停止。scaling 依然是通向更高智能的主要路径，这一点没有变，变的是 scaling 什么东西。今天决定一个模型上限的是四个因素的组合：基座规模、有效深度、训练深度、任务环境。四者边际收益不同，随阶段轮换，公司的资源分配就是在不同阶段判断哪个因素当前回报最高。GLM-5.3 证明了训练深度是当下余量最大的旋钮，而把后训练做到极致之后，下一阶段增长必须回到基座。GLM-5.3 Flash 已经用新一代架构和 30T 多模态语料验证了效率。下一代基座模型的训练已经在路上，方向是包括更大的有效规模、更长的原生上下文，以及原生多模态的统一建模。

Fully self-training：数据自产、环境自造、基础设施自优化
第三点，在系统层面实现 fully self-training。更深一层的变化发生在训练系统内部：数据、环境、基础设施都出现了被 AI 接管的早期证据。数据开始自产，model vs model 的自我对弈管线，让数据质量的上限不再取决于人类标注的速度，而取决于模型自身的验证能力。环境开始制造，研究智能体采集任务模式，裁决裁判智能体逐一试做，验证器自动合成环境，成了流水线上的标准产品。基础设施开始自我优化，推理系统的优化本质上就是代码工程任务，而这恰恰是模型最强的能力域。三条线指向了同一个终局：模型参与自身的改进，形成递归式的自我改进，这就是我们的技术愿景 fully self-training——下一代的 GLM 将在上一代 GLM 搭建的环境里实现自训练。

边界与治理：能力越强，越需要把评估判断交给外部
第四点，边界与治理。能力越强，越需要把评估和判断交给外部：对模型能力的评估、对风险的判断，最终必须由人来裁量，并且引入外部机构独立评估。上半年在网络安全方面我们已经这样做了：最敏感的能力受控，实现受控开放，开源之前由第三方专业团队独立评估；漏洞通过国家漏洞库完成责任披露；基准分数由我们自己报告，风险判断交给外部团队。这个分工不会因为能力提升而改变，只会随着能力的上移而加强。

先有能力，再有生意——模型能力是所有产品与商业逻辑的起点
最后，我想把今天所有的数字收回到一句话上：模型能力的代际水平，是公司所有产品与商业逻辑的起点。从 GLM 预训练架构到悟道系列，再到今天的 GLM-5 系列，七年时间我们专注做的基本只有一件事：训练更强的模型。而收入的每一次快速增长，都发生在模型能力提升、新的任务场景被解锁之后，而不是之前。先有能力，再有生意。上半年收入结构的翻转和量价齐升已经验证了这套逻辑，接下来就轮到更大的用户规模、商业规模和全球影响力来继续验证它。路还长，但方向笃定。谢谢大家。

唐杰：单点领先有时限，持续迭代能力更重要
唐杰：谢谢 Olivia 的提问。坦率地讲，第一，我们非常诚实地认为，任何单点的领先肯定都是有时限的。今天一个 coding benchmark 的第一——确实这些 benchmark 都是以周或者以月为单位去更新的，很快就会被追平，所以市场有 up and down，bench 上也会有 up and down。所以在这一次的半年报当中，我们也很诚实地表达了我们对 SOTA 的理解。领先多久这个问题，可能更值得追问的是持续领先的能力有多强。回顾过去大概 11 个月，我们的整个 GLM 模型家族从 4.6、4.7、5、5.1、5.2 到 5.3，连续完成了多代的迭代，整个能力曲线持续一直在往上走，同时单位任务成本也基本保持在一个相对比较健康的水平。这对我们而言是一种持续迭代的能力，它比某一次单一的榜单的第一会更重要。

Coding是技术逻辑的卡点：提供规模化、自动化、低成本的可验证环境
第二，我们对 coding 的理解，其实并不是把它当成一个 go-to-market 的角度，或者是说从商业的角度看收入很快的一个产品线，它更像是我们所理解的整个技术逻辑上必须去突破的一个卡点。因为沿着 coding 往下走，我们才能真正往 agentic、往长程任务、往 AaaS、往我们最后讲的 fully self-training 这个方向上去演进。
原因其实也比较具体：一个 coding agent 要去完成一个复杂的工程任务，同时还需要做需求理解、任务拆解、代码阅读、工具调用、修改代码、运行测试等等，最后还要重新规划、验证结果。更重要的是，它在这一整套环境和工作流当中，其实有一个非常强的正反馈，这是我们无论从技术逻辑上还是从产品逻辑上选择 coding 入手的一个原因：代码能不能运行，测试过不过，性能有没有改善，bug 有没有修好，它首先是非常清楚的、可以客观验证的。这个问题对于强化学习是非常重要的，因为很多知识工作最大的问题其实不是模型会不会做，而是很难判断到底有没有做对。coding 恰好提供了一个规模化的、自动化的、低成本的 verifying 场景。所以模型每执行一次任务，它都可以获得一个真实环境的反馈，因此非常适合去训练多步规划、工具调用、错误恢复、长程任务的执行、自我修正这一系列的能力。
比如说我们的智谱 GLM-5.3，整个训练环境已经进一步从传统的 coding exercises，扩展到了真实的专家工程任务上面去，一些专门的任务其实已经相当于资深工程师数天的工作，所以这是非常重要的一点。上述的这些思考是想跟各位分享：coding 这方面的能力从逻辑上而言已经是可泛化、可以迁移的，而不仅仅是我们限于这个场景的一个预设。

能力迁移实证：网络安全CyberGym 84.5%，真实漏洞2436个
比如 5.3 其实在前沿工程能力之外，还涌现出了一个特别的能力，就是我们讲的网络安全 cyber security，它也是一个很清楚的例子。整个网络安全漏洞的发现，并不是一个简单的背 CVE 的逻辑，它真正的困难点在于模型怎么去理解代码、怎么去发现异常、怎么去调用工具验证、去建立多阶段的攻击与防御（特别是网络安全防御这方面的能力），并根据环境的反馈去持续调整方案。这和复杂的 coding agent 所需要的底层能力其实是高度一致的，以及是在这个基础上的一个延伸。
随着我们整个 5.3 的能力扩大到长程任务的环境、以及后训练这一块的加强，我们能看到在网络安全能力上，5.3 出现了非常明显的提升。如刚才我们董事长刘德兵先生介绍的那样，在 CyberGym 当中，5.2 当时的分数大概是 77.2，5.3 直接提升了接近 7 个百分点，到 84.5。ExploitBench 上，5.2 的时候大概是 24.4 的一个分数，5.3 直接提升了 30 个百分点到 54.4。而且还有一个很有意思的现象：越往完整的 exploitation chain 这种需要长程规划的任务去走，5.3 相比 5.2 的提升会越明显。
我们也把这一整套能力，放到了一个真实的代码环境当中去验证，看看是不是我们的一个错判。实际上结果是非常强有力的支撑：从 5.2 以来，公司就已经在和多家国内的安全团队来合作，在真实的代码库当中，累计发现并经过专家筛选去重的漏洞达到了 2436 个，其中有超过 1000 个是高危漏洞，覆盖了 269 个项目。这个结果其实我们会觉得，比单纯的 benchmark 要更重要，因为它说明从 coding 里面训练出来的长程任务能力，已经顺着它的延伸，非常自然地迁移到了网络安全这种新的专业任务场景当中去了。

Cowork三标准：高智力门槛、可有效验证、高经济价值
所以我们总结一下，并不会简单把这个 coding 的领先，或者 coding 这一块的护城河，直接定义成 coding 在一些 bench 上面永远领先别人多少分。我们真正希望的，是能够建立一个长效的能力牵引的机制：通过 coding 本身提供高密度的可验证环境，去训练模型长程规划、工具调用、错误恢复这些的能力，再把这些能力迁移到比如刚才举的例子 cyber security，以及数据分析、复杂自动化和更多专业方向的一系列 cowork。
就像我们刚才介绍的，我们自己已经非常清楚地意识到，coding 继续往下走，非常自然的一个延伸就是协同工作。但这个 cowork 可能和一开始大家理解的所谓办公是完全不一样的：它不是一个日常内容的辅助，恰恰是在更多的极其专业的领域，对真实复杂工作流当中的一个替代。所以我们后面的整个 cowork 场景，也不是靠拍脑袋直接选的，我们其实有三个非常清晰的标准：第一个看这一系列的任务有没有足够高的智力门槛；第二个看这些任务能不能被有效的验证；第三个要看完成这些任务有没有足够高的经济价值。目前网络安全确实是验证出来最清晰的一站。除了网络安全之外，如刚才介绍，法律、金融、数据分析这些方向我们也在尝试，但因为可靠性的门槛和验证机制不一样，整个商业化的节奏也不一样。
所以 coding 的持续领先，以及是不是能够在每一个 bench 上面去持续领先，这个其实不是最本质的问题。真正重要的一个问题是：当 coding 继续往下延伸的时候，我们能不能很自然地把这套能力迁移到下一层，特别是 cowork 这个层面更复杂、更高价值的任务上面去。如果每一代模型都能承担比上一代模型更长、更完整、更专业的工作，那么 coding 本身就变成了一个原能力，就是 Meta Ability，或者说基础能力，公司能够服务的高价值任务边界就会持续向外扩张。这个迁移速度，以及这种迭代速度、沿着能力不断去解锁新场景的速度，才是我们想真正建立的一个长期壁垒。好，我先回答到这。

第一个，整个算力供给的问题，现在在中国的模型公司、在行业内，其实面临的都是一个共性问题。从智谱的角度而言，我们一直在努力地去获得算力的新的扩容和储备，所以我们的算力确实今年以来一直沿着一个非常健康的节奏不断地在持续扩张，在训练侧和推理侧这两侧都在增加投入。
但是我们现在可能已经说到下半场了，行业内大家也越来越意识到，可能不能简单地用一个你有多少张卡，或者是某种型号的卡的数量，去衡量一个公司在算力的支持和供给侧这样的一个能力了。原因在于，我相信大多数行业内的公司今天都一样：算力的来源和用途都已经比较多元化了。以智谱为例，我们整个算力资源的来源，可能同时包括了自有集群、算力的租赁和算力的服务采购；用途上，也投入到不同的方向上，比如说预训练、中训练、后训练以及生产推理。不同代际的、不同架构的芯片，简单说就叫做多元异构，它的实际的训练效率和推理的吞吐差异其实是非常大的。所以简单把这些卡加起来，不是一个简单的数学问题，并不能直接反映一个算力供给和 infra 这方面的能力。
那我们内部比较关注什么？除了从商业的角度和报表健康度的角度，刚才提到了算力乘数的概念，另外一个概念是我们更关注的有效算力。简单讲，就是有多少算力已经安装、能够稳定地调度、能够长期地运行，最后转化成模型训练可用的这些 token。所以对于一个大模型公司而言，本质上要回答的问题不是说你有多少张卡，而是这些资源最终能支持多快的模型迭代速度，以及能有多大规模的商业化 token 供给。

推理侧：10万卡国产芯片经受60万亿token超大规模流量考验
过往半年，行业内也有一个非常大的变化：因为我们推理侧业务的体量都已经到了一个比较大的规模，所以大家相信都不会把单一渠道的来源，无论是进口卡还是国内卡，作为一个唯一的规模化路径。截止今年上半年，公司已经实现了大概在 10 万卡这个级别上的国产芯片的规模化低成本推理。GLM-5.3 这一次的模型发布当中，其实也做了一次超大规模真实流量下的一个实验：我们最早这个 ox-alpha 是匿名上线，但背后我们是全面使用了国产芯片的集群来提供服务。我们当时就是想试一下，在一个超大规模的流量上会怎么样，最后事实确实也经受住了考验：当时 6 天大概 60 万亿 token 的调用，无论对于 OpenRouter 还是 OpenCode 这两个平台而言，都是历史级的、从来没有经受过的超大流量。我们非常自豪，我们的国产卡承受住了这样超大规模的流量推理，而且提供了非常好的一个服务。

深水区：国产卡经济性验证，infra能力使端到端性能提升3倍
这里的关键，我觉得我们已经要更进一步了：在看算力这一侧的问题的时候，不仅仅是在看国产卡能不能跑——我觉得这一次 5.3 Flash 已经证明了，国产的加速卡和推理卡肯定是能跑得很好的——但是现在进入到深水区的问题是，怎么去验证国产卡它的一个经济性。针对国产卡或者说国产芯片，它在显存容量、带宽、长上下文的约束这些方面的客观情况，每个模型公司我觉得都一样，但这里面会有能力上不同的资源投入和侧重的方向。智谱其实从半年前开始，就有一个 all in infra 的策略，我们非常重视整个算力 infra 这一块的投入。从这一次 5.3 开始，我们重新做了推理引擎和服务栈，包括编码解码（encode、decode）、PD 分离这一块的量化，包括 layer split，包括缓存通讯优化这一块的工作。5.3 发布的时候我们也有过一次披露，对标的结果是：在相同的国产硬件或者说算力基础上，这一套整体基础设施的能力，端到端相比初始的基线实现了 3 倍的服务性能提升。
这件事情非常具有象征性意义。因为它实际上意味着：你面对一个有限的资源、一个非常复杂的算力供给的环境，怎么通过本身 infra 上能力的提升，让你在限定范围的算力供给的情况下，能够用更高的效率去持续供给更优质的 token。它比我们简单地说，通过一些渠道或者各种各样的办法，尽可能地扩张算力来源（无论是海外卡的来源还是其他），可能是更本质一点的，也是未来大家会越来越多去面对的问题。这是大概在推理侧的情况。

训练侧：结构性错配正在改善，3-6个月内国产卡将放量
那训练侧的情况是稍有不同。前沿模型的训练，对于算力的要求现在越来越是一个结构的要求，而不是一个量上的要求，特别是对于大的同构集群的稳定性——网络通信、软件栈还有长期运行的要求其实是非常高的。目前是一个结构性的错配，但是也在慢慢地改善：国内目前的算力环境当中，现状还是以异构算力为主的，主要是国产卡的供给，现在还没有到一个非常大的放量的阶段。但是我相信可能在很快的 3 个月到 6 个月内，我们能看到大量的先进的国产卡厂商迎来算力放量，到那个时候，目前这种异构算力并行的情况能得到比较大的改善。我们下一代的基模的训练，已经在推进当中了，在算力配置上会优先去保证关键的训练窗口，不会因为现在推理侧需求的历史性放量，就把所有的资源都堆到推理上面去。
总结一下来看：第一，在算力侧，整个物理算力供给的扩容肯定会继续进行；第二，从结构上来看，会有更多的国产芯片进入到规模化的推理；第三，对于大模型公司越来越重要的一件事情，就是你的 infra 能力——怎么通过模型和 infra 的优化，去提高每单位物理算力能够产生的有效 token，同时你的算力乘数能不能继续提升。所以这可能是我们的一个思考，也就是下一阶段我们给自己定位的：真正的主要矛盾是怎么把每一单位算力，转化成最多的智能、最多的有效 token 和最多的商业价值，这个是我们的思考。

刘德兵：单点SOTA不能形成长期定价权，四个差距构建壁垒
刘德兵：好，我先来回答一下第一个问题。我们这边也认可：单点的 SOTA 本身并不能形成长期的定价权，今天某个 benchmark 第一，可能在几周之后就会被追平。所以我们真正想建立的，不是永远保持某一个榜单第一，而是持续地把能力、成本前沿往外推的这么一个能力。我们来主要看四个东西。
第一个是迭代的速度。在过去的约 11 个月里边，智谱 GLM 从 4.6、4.7 然后到 5.3 连续迭代了 6 代，Artificial Analysis 上的智能指数从 32 提升到了 60，同是旗舰模型，单任务成本基本维持在 0.2 美元量级；然后智谱 GLM-5.3 Flash，又把这个成本进一步推进到了约 0.045 美元。单次领先是可以被复制的，但是如果一个团队能够持续地以较快的节奏提高智能，同时控制单位任务成本，这条能力曲线就更难被复制。
第二个，是从 benchmark 拉开到真实任务的完成率。短任务、短回答、知识类或很多公开 benchmark 的能力一定会越来越趋同，但任务越长，差异反而会越容易被放大。让两个模型回答同一道题，可能只是差几分；但让它们连续执行几个小时的软件工程任务，要自己理解代码库、调用工具、处理失败、重规划并最终交付结果，差距会非常明显。GLM-5.3 的训练和评测，已经越来越多地转向了这种长程可执行、可验证的真实环境，而不只是追逐静态的题库。
第三个，是从低价值任务进入高价值任务。真正决定定价权的不是 token 本身，而是这些 token 最终能完成什么任务。同样 100 万 token，用来闲聊，或用来完成一个工程任务、工程项目、修复一个生产系统的漏洞，对于客户创造的价值是完全不同的。所以我们的路径是从 coding 走向 agent、coworker：模型能够承担的任务越完整，客户购买的东西就越从 token 接近于任务的结果。到了这个阶段，客户更关心的是一次任务能不能完成、减少多少工程师时间、降低多少错误或风险，而不是单纯比较每百万 token 便宜了几毛钱。
第四个，是进入客户工作流以后，形成使用深度或迁移成本。基础模型最终不是一个孤立的 API。模型一旦进入客户的代码库、工具链、harness、内部数据和工作流程，客户就会围绕它积累 prompt、agent workflow、权限体系、评测标准、工程集成。这些时候切换模型，考虑的就不只是 API 的单价，而是整体的任务完成率、稳定性以及重新适配的成本。

商业数据验证：价格+101%同时调用量大增，前十大用户+98倍
上半年的商业数据已经开始验证了这个逻辑：API 平均售价提高约 101% 的同时，token 调用量仍然在大幅度增加；按收入计，前十大用户的日均调用量较年初增长了 98 倍。换句话说，我们看到价格在提高，但核心客户反而用得更深。这就说明用户不是单纯因为模型便宜才使用，而是在模型能力提高以后，愿意把更多真实任务交给它，并为更强的能力支付更高的价格。
所以我们认为未来行业会出现两条价格曲线：一是同等智能的价格一定会持续下降，Flash 就是在做这个事情；但对于真正能够打开新的任务边界、显著提升任务成功率的 frontier model，仍然会有 premier 甚至是有更进一步提价的空间。我们真正希望拉开的，不是某一个 benchmark 的几分，而是四个差距：更快的模型迭代、更高的真实任务完成率、更低的单位智能成本，以及进入更高价值的工作流。只有这四件事持续地成立，单次 SOTA 被追平并不会消灭定价权，真正决定定价权的，是用户在下一次更难的任务时，是否能够优先选择我们的模型。好，谢谢。

肖涵：出海从主权大模型转向开放平台API，双帕累托最优卡位
肖涵：我来补充一下您刚才的第二个问题，就是关于整个海外，无论是商业上的还是模型竞争上的一些考量和进展。其实智谱在 25 年开始，就已经有比较有规模意义的出海业务。当然像刚才说的，分阶段来看，在最早我们卖本地化部署这种形态的时候，海外业务出海的形态是以主权大模型项目为主的。当时我们也披露过大家熟知的马来西亚的主权大模型项目，那个是智谱最早通过本地化部署这种方式去进行的出海尝试。后期，随着我们整个业务形态发生了一个质变，目前业务的主体已经转向了开放平台和 API 这一块的业务。

另外一方面，我们也发现模型从原来简单的回答问题——一开始基座模型训得越来越大的时候，能把很多知识给存进去——到后来，应用的需求以及智能上界越来越多地偏向做事情，所以我们慢慢地把工作重心也转向了 coding，转向甚至是最近转向的像 cowork 这样的一些工作上面。

下一代方向：基座更大+loop深度推理+重后训练+fully self-training
对于下一代的研究，我们更多的也是一样的一个思路。第一，现在网上的文本数据其实已经没有那么多了，而且更多的时候我们在用合成的数据。所以对于基座模型，我们首先会进一步 scaling，把基座模型做得更大：一方面基座模型做大，会存储更多的知识，并且把这种知识表示得更好，也就使得智能上界的天花板更大。另外一方面，我们还会做很多比如增加推理能力的工作。原来的推理能力就是让它增加很多 thinking，这样的话，训练模型的时候必须把这个模型的激活做得特别大；但是激活做得特别大的时候，它就会特别慢。比如训一个很大的几 T 的模型，如果激活也做得特别大，推理速度就会很慢，可能每秒钟只有几十个 token，而且推理的成本也特别高，这样这个模型就很难普惠地使用。所以我们现在也会采用很多新的技术：通过不大的激活，但是通过 loop 的方式，使得激活能够做更深度的推理，这样就可以把推理成本做得比较低，这是我们第二个思考的思路。
另外一方面，在后训练方面我们会大大地加强：不仅是根据基座，还会把后训练做得很重。说实话，我们中国的这种算力，永远还是赶不上美国像 OpenAI 还有 Anthropic 的这样的算力，于是我们必须想用一些新的技术方法、包括工程的方法，所以我们在后训练方面现在有自己的优势。因为早年 OpenAI 在 2022 年 11 月 30 号发布 ChatGPT 的时候，我们当时就成立了一个几百人的数据标注团队，所以我们在数据环境搭建上面花了很多功夫。这也是这一次大家看到 5.3 的发布，一下子就比 5.2 的效果好了很多的原因：我们在数据环境上搭建了几十倍的数据环境，效果一下就大大地提升了。所以 scaling 数据环境也是我们做了很多相关工作的地方，未来我们也会进一步把它增强。

6.0定义为fully self-training（RSI）：最大难题是模型能自己判断何时停止、纠正自己
当然最重要的未来，如果你真要提到 6.0 这样的一个模型，我觉得我把它定义为叫做 fully self-training，也就是在美国那边很多人会把它叫做 RSI，也就是这个模型具有自进化的一个能力：包括从预训练到 mid-training，再到 post-training，它都可以完全地自己训练自己，而且做自进化。这其实是一个很大的挑战，这个挑战最大的问题是：这个模型能自己判断自己什么时候停止、什么时候能够纠正自己，这是最大的难题，而不是一个简单让模型训大、直接往下训。所以这个在未来模型中，我们会作为一个重点来做研究。当然刚才也提到，在未来的研究中，我们还会把伦理、把社会治理考虑进模型中，这也是我们下一步的一些考量。好，感谢提问。
